# 18 · 執政官 Steward

> 每位玩家都是一位獨立的**城主（領主）**，並配有一位**執政官**。
> 執政官在領主不在時，依照領主訂下的**施政方針**持續執行擴張與建設。
> 領主隨時可以接管。

## 1. 為什麼需要執政官

12 天的賽季裡，一覺 8 小時等於 **10 個遊戲日**——而領土佇列會整整空轉 8 小時。
沒有執政官，這個遊戲會變成「誰睡得少誰贏」，
直接違背 P3（可離線推進）與「休閒玩家戰力不應低於硬核玩家 50%」的設計檢查點
（見 `03-economy.md` §6）。

行軍計時制已經解決了「戰鬥要盯著螢幕」的問題，
但沒有解決「**佇列空了沒人補**」的問題。執政官補上這個缺口。

## 2. 鐵則：執行者，不是決策者

> **執政官執行你的政策，不替你做決策。**

這條線不能模糊。整份企劃的核心是「選擇本身就是玩法」（`00` §3 支柱 5），
如果執政官替你做選擇，玩法就被拿走了。

| 執政官**可以**做 | 執政官**永遠不能**做 |
| --- | --- |
| 拓荒佔領相鄰的中立格 | **核心建造佇列**（主堡與 B/C/D）——最尖銳的取捨 |
| 建造／升級領土設施 | **任何軍事行動**：攻擊、突襲、增援、遺跡駐防、召回 |
| 招募兵種（依你設定的配比） | 拆除任何建築 |
| — | 聯盟事務：加入、退出、邀請、聊天 |
| — | 集市掛單與交易 |
| — | 動用你設定為「保留」的資源 |

**核心佇列與軍事決策永遠手動。** 這兩件事是這個遊戲的全部樂趣，
交給執政官等於不玩了。

## 3. 執政官只在佇列閒置時行動

這是整個系統最重要的設計，它讓「玩家 vs 執政官」的衝突**根本不會發生**：

```
領土佇列空閒 → 執政官可以拓荒或建設
招募佇列空閒 → 執政官可以募兵
核心佇列     → 執政官永遠不碰

任何佇列只要玩家自己排了東西，執政官就沒有回合。
```

於是：

- **積極遊玩的玩家**：佇列永遠是滿的，執政官幾乎不會動作
- **每天上線 3 次的玩家**：執政官填補中間的空檔
- **睡覺的 8 小時**：執政官讓領土持續成長

**你玩得越勤，執政官越沒事做。** 不需要任何衝突解決邏輯。

## 4. 施政方針 Directives

領主設定方針，執政官依方針執行。方針隨時可改，立即生效。

### 4.1 三個方針

| 方針 | 玩家可設定 | 執政官行為 |
| --- | --- | --- |
| **拓荒 Expansion** | 開/關・方向偏好（朝遺跡／朝荒野／就近）・資源保留下限 | 領土佇列閒置時，選一格合法相鄰中立格派出拓荒隊 |
| **建設 Development** | 開/關・設施優先序（糧／木／石／鐵／哨塔）・資源保留下限 | 領土佇列閒置時，依優先序新建或升級設施 |
| **募兵 Levy** | 開/關・兵種配比・**人口保留下限**・資源保留下限 | 招募佇列閒置時，依配比招兵 |

★ **一座生產建築 = 一條招募佇列**（兵營／獸廄／工坊），
民兵另有一條不需要建築的佇列。所以「同時能招幾種兵」直接等於
「你在 B/C/D 三格裡放了幾座生產建築」—— 7 選 3 的取捨延伸到了軍事。

★ 規劃與執行**必須共用同一個可負擔性函式**（`maxAffordable`）。
第一版的募兵自己算了一次「買得起幾個」，漏掉「一次下的單不能超過
倉庫容量」那一條，於是排出一個保證失敗的動作、每輪在簡報留一筆
BLOCKED。見 `11` §18.2。

### 4.2 ★ 資源保留下限：讓取捨留在玩家手上

每個方針都有一組**保留下限**：

```
「拓荒方針：木材保留 5,000 以下不動用」
→ 執政官只會花掉 5,000 以上的部分
```

這一個設定就保住了整套取捨系統：
你正在存木材要升主堡 Lv18，執政官不會把它花在拓荒上。

**沒有這個閥門，執政官就會替你做完所有的資源分配決策**——
而那正是 `03-economy.md` §7 說的「遊戲的樂趣不在累積資源，在決定資源要去哪裡」。

### 4.3 可同時啟用的方針數，由主堡等級決定

| 主堡等級 | 可同時啟用 |
| --- | --- |
| Lv1–7 | **1 個** |
| Lv8–15 | 2 個 |
| Lv16+ | 3 個（全開） |

早期只能開一個，於是又是一個取捨：
**「我要執政官幫我拓荒，還是幫我募兵？」**

這也讓主堡多了一個升級理由，且不需要新增任何建築
（核心只有 4 格，不能再擠）。

## 5. 執政官刻意不是最優解

如果全權委託跟親自操作一樣好，就沒有理由登入了。
執政官的行為**刻意保守且次優**：

| 情境 | 執政官 | 親自操作可以 |
| --- | --- | --- |
| 選拓荒目標 | 選**最近的合法格** | 挑 `LODE` / `FOREST` 等高價值地形 |
| 領土形狀 | 就近向外攤 | 刻意經營「厚實」版圖，避免細頸（見 `02` §2.3） |
| 設施選址 | 依優先序找第一個空格 | 把哨塔放在細頸、農田放在非森林格 |
| 募兵時機 | 佇列一空就補 | 依對手兵種調整配比、卡在戰前一次爆兵 |
| 資源使用 | 保留下限以上就花 | 精算到下一次升級剛好夠 |

**目標差距**：完全委託的玩家，第 12 天的總戰力應為
積極玩家的 **75–85%**。
夠高，讓休閒玩家不被甩開；夠低，讓登入仍然值得。

## 6. 領主接管 Takeover

領主隨時可以收回控制權，三種粒度：

| 動作 | 效果 |
| --- | --- |
| **關閉單一方針** | 該項不再自動執行，其餘照常 |
| **暫停執政官 N 小時** | 全部停手（預設 6 小時，可自訂 1–24） |
| **召回進行中的拓荒隊** | 執政官派出的拓荒隊在立旗完成前皆可召回 |

另外，**玩家的任何手動操作都自動優先**——
因為執政官只在佇列閒置時行動，你一旦排入指令，它就沒有回合（見 §3）。

## 7. ★ 施政簡報：回歸時的第一個畫面

執政官不只是背景自動化，它是**重新進入遊戲的敘事介面**。

登入時，取代一整面的通知牆，玩家看到的是一份簡報：

```
┌──────────────────────────────────────────┐
│ 執政官 · 灰喉                              │
│ 廢曆 41 年 3 月 14 日 — 您離開了 9 小時      │
├──────────────────────────────────────────┤
│ ▸ 拓荒 2 格：第 47 區 · 鏽谷 (218,341)      │
│ ▸ 農田 (215,339) 升至 Lv6                  │
│ ▸ 招募 劍士 ×40、長矛兵 ×25                 │
│                                          │
│ ⚠ 領主，糧食將於 4 小時後溢出               │
│ ⚠ 第 47 區容量剩餘 1,150（冬季將至）         │
│                                          │
│ 🗡 期間您遭受 1 次突襲（損失 木 340）        │
│    [ 查看戰報 ]                            │
├──────────────────────────────────────────┤
│        [ 知道了 ]      [ 調整方針 ]         │
└──────────────────────────────────────────┘
```

這把「結算離線期間的一切」（`00` §5.1 短循環的第一步）
從**一堆待處理事項**變成**一位下屬的回報**。

同一份資訊，完全不同的體感——而且它讓遊戲曆
（見 `14` §2）與廢土敘事真正落地在每次登入的第一秒。

## 8. 與 AI 託管的關係：合併為同一個系統

原設計有一套獨立的「AI 託管」（連續 48 小時未登入 → AI Settler 接管，見 `15` §6）。
現在把它併入執政官，成為**權限層級**而非兩套系統：

| 狀態 | 執政官權限 |
| --- | --- |
| **方針模式**（預設） | 拓荒／建設／募兵，受方針與保留下限約束 |
| **全權代理**（連續 48 小時未登入） | 額外獲得**防守調度**與**核心佇列**權限，行為等同 AI Settler 性格 |
| **領主回歸** | 立即收回全權，回到方針模式 |

- 全權代理期間在地圖上顯示 `⚑全權` 標記，**不隱瞞**
- 全權代理**仍然不會主動攻擊他人、不會退盟、不會交易**
- 全權代理**不提供任何防禦加成**——否則就是離線無敵的漏洞

未首次登入 6 小時的帳號則直接轉為 AI（見 `15` §6），
那是另一回事：那個位置根本沒有領主。

## 9. 執政官的名字與形象

- 賽季開始時由 seed 生成一個廢土風格的名字（「灰喉」「三號書記」「斷指」）
- 一張 32×32 像素頭像（隨機組合：性別中立的兜帽、面罩、義眼、傷疤）——
  4 × 4 × 3 × 3 × 3 = **432 種組合**（`lib/game/avatar.ts`）
- 玩家可**重新命名**（純外觀，免費，上限 12 字元）
- v1 **不做性格差異**——每位執政官行為完全相同。
  性格化（謹慎型／激進型，影響選點傾向）留給 v2

★ 頭像**左右對稱地生成**：只算左半邊再鏡射，隨機組合才會看起來像
「一張臉」而不是一堆雜訊；義眼與傷疤刻意不對稱，在鏡射之後才畫上去。
輸出是調色盤索引陣列，要畫成 SVG 還是貼圖是渲染層的事 ——
`/lib/game` 不碰渲染。美術資源進來時換掉部件即可，組合邏輯不用改。

## 10. 絕不販售

| 項目 | 是否販售 |
| --- | --- |
| 執政官本身 | ❌ 所有人從第 1 天就有 |
| 額外方針欄位 | ❌ **只能靠主堡等級解鎖** |
| 執政官行動頻率 | ❌ 不可購買 |
| 執政官皮膚與名字 | ✅ 純外觀 |

額外方針欄位是**戰力**（更多自動化 = 更快成長），
販售它會直接違反 P4「付費不買戰力」。
`00-overview.md` §7 的商業模式表已同步更新。

## 11. 實作

### 11.1 觸發時機：事件驅動 + 安全網

執政官**不需要自己的高頻 tick**：

```
主要觸發（零額外負載）：
  結算迴圈（/api/cron/settle，軌道 B）掃到到期的
  CLAIM_DONE / BUILD_DONE / TRAIN_DONE 時，
  同一交易內評估執政官方針

安全網：
  每位玩家每 2 真實小時一個 STEWARD_TICK 事件，
  處理「佇列本來就是空的」的情況
```

600 玩家 × 12 tick/日 = 7,200 次/日 ≈ **每分鐘 5 次**，可忽略。

★ 兩個觸發點都在**伺服器端**，不含頁面載入。曾經考慮過「玩家打開
領土畫面時順便跑一次」，但那會出現一個很糟的情境：領主正要點一塊
`LODE`，執政官搶先用掉那條佇列去拓最近的沼澤 —— 而它做的完全符合規則。

★ 排下一個 tick 之前要先確認**沒有未結算的 tick**。一次執行可能被
多個到期事件觸發，每次都排一個就會自我繁殖，幾小時後變成 tick 風暴。

### 11.2 走與玩家相同的驗證路徑

執政官的每一個動作都呼叫**與玩家完全相同的 Server Action**
（`claimTile` / `buildFacility` / `trainUnits`），不開後門。

若動作不合法（資源不足、佇列已滿、領土容量已滿、超出保留下限），
它就是失敗——執政官不可能作弊，也成為規則系統的壓力測試。
這與 AI 玩家（`15` §7.1）、遺跡軍團（`17` §6）採同一原則。

★ 實作時才發現這條規則會**影響架構**：Server Action 的第一件事是
從 session 解出「我是誰」，而執政官沒有 session。所以把
**身分解析**與**規則驗證**切開：

```
Server Action ── auth() → playerId ──┐
                                     ├──→ lib/server/base-ops.ts
執政官        ── 明確傳入 playerId ──┘      （唯一的驗證路徑）
```

三個非人類行動者共用同一條路徑，等於三個獨立的規則系統壓力測試。

### 11.3 決策函式是純函式

```
/lib/game/steward.ts
  decideStewardActions(input) → { actions, blocked, warnings }
```

無 I/O、可單元測試、可在 `simulate-season.ts` 中大量重放。
模擬腳本裡的「完全委託玩家」就是**啟用全部方針且從不手動操作**的玩家——
§5 的 75–85% 目標可以直接被驗證。

★ **回傳型別裡沒有「升主堡」「出兵」「拆除」「掛單」這些動作。**
§2 的禁區不是靠檢查擋下來的，是根本沒有那個 case ——
一條規則如果只能靠審查來維持，它遲早會被繞過。

★ 決策函式只接收**地理事實**（距離、地形、鄰居），成本由它自己算。
拓荒成本隨已有領土遞增，而同一輪可能連拓好幾格，
呼叫端先算好的那個數字在第二格就已經過期了。

### 11.4 資料模型

```sql
CREATE TABLE stewards (
  player_id     BIGINT PRIMARY KEY REFERENCES players(id),
  name          TEXT   NOT NULL,
  avatar_seed   INT    NOT NULL,
  directives    JSONB  NOT NULL,   -- 三個方針的開關、參數與保留下限
  paused_until  TIMESTAMPTZ,       -- 領主接管中
  full_proxy    BOOLEAN NOT NULL DEFAULT false,  -- 48h 未登入 → 全權代理
  last_acted_at TIMESTAMPTZ
);

-- 簡報：離線期間執政官與世界的行為，登入時彙整顯示
CREATE TABLE steward_log (
  id         BIGSERIAL PRIMARY KEY,
  player_id  BIGINT NOT NULL REFERENCES players(id),
  kind       TEXT   NOT NULL,   -- CLAIM | BUILD | LEVY | WARNING | BLOCKED
  payload    JSONB  NOT NULL,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE INDEX steward_log_player_idx ON steward_log (player_id, created_at DESC);
```

`steward_log` 只保留 48 小時，登入生成簡報後標記已讀。

`BLOCKED` 類型很重要：當執政官因為保留下限或容量上限而**沒能行動**時，
也要記錄並在簡報中告訴領主——
「木材保留下限 5,000，本可再拓荒 2 格」。
**執政官沒做什麼，跟它做了什麼一樣需要被看見。**

★ 但 `BLOCKED` 要**去重**。保留下限沒改就會每一輪都擋一次，
兩小時一個 tick，離線一晚回來會看到同一句話 12 遍。
同方針 + 同原因在 6 小時內只記一次 ——
簡報的價值就在於它**不是**一面通知牆（§7）。

## 12. 平衡驗證

- [x] 完全委託的玩家，第 12 天總戰力為積極玩家的 **75–85%** —— 實測 **80%**
- [ ] ~~每日上線 3 次的玩家，其領土佇列閒置時間 **< 15%**~~
      **這一條量錯了東西。** 實測休閒 56%、**積極玩家 58%** ——
      閒置的成因是**資源**不是注意力，而那不是執政官補得了的東西
      （也不該由它來補，那會違反 §5 的刻意次優）。
      門檻要等 M3 之後重訂，屆時閒置的成因結構會再變一次。見 `11` §17.2
- [ ] 每日上線 10 次的玩家，執政官實際動作次數佔其總動作 **< 20%**
      （驗證積極玩家的佇列本來就是滿的）
- [x] **核心佇列的閒置率不因執政官而下降**
      （驗證執政官確實沒碰核心佇列——這是取捨系統的命脈）
      —— 實測 **1.41×**（完全委託 ÷ 積極）。
      這個比值掉到 1 以下就代表有東西伸手進了核心佇列，
      而那種越界不會有錯誤訊息，只會表現為「大家的發展曲線悄悄變得比較像」
- [ ] 啟用「拓荒」方針的玩家，其領土形狀的「細頸數」比手動玩家**多 20–50%**
      （驗證執政官確實次優，且創造了可被利用的弱點）
- [ ] 簡報的 `BLOCKED` 事件中，**≥ 60%** 的玩家在看到後 3 次登入內調整了保留下限
      （驗證簡報有效傳達了資訊）

## 13. 待決議

- **F1**：執政官是否該在「即將被攻擊」時自動做任何事（例如把資源塞進地窖）？
  傾向：**不做**。防守是玩家決策，而且地窖是自動生效的，沒有可操作空間。
- **F2**：v2 的執政官性格（謹慎／激進／均衡）該怎麼取得？
  傾向：賽季傳承點兌換，純粹改變選點傾向而非效率——**不可販售**。
- **F3**：簡報是否該支援「離線超過 24 小時」的長摘要與時間軸？
  傾向：需要。12 天的賽季裡離線 24 小時是重大事件，
  簡報應轉為逐日時間軸而非單一列表。
