## M1 · 世界與地圖渲染

**產出**：能看、能縮放、能移動的 500×500 地圖

- [ ] `scripts/generate-map.ts`：seed → 地形 → 64 個 chunk 二進位檔
- [ ] 遺跡放置演算法 + 約束驗證
- [ ] 三分天下：以行軍成本距離做 Voronoi 分割成三個陣營區域
- [ ] 出生點批次分配：固定環帶（20–45 / 45–78 / 78–105）+ Poisson-disk + 同行小隊群集
- [ ] 環帶被 Voronoi 邊界裁切時，外半徑自動向遠離他陣營方向延伸
- [ ] **五項公平性驗證**，未通過自動換 seed 重跑（見 `13` §3）
- [ ] PixiJS v8 場景：terrain / territory / structure / march / overlay 五層
- [ ] Texture atlas 與地形貼圖（先用色塊佔位，美術後補）
- [ ] 視野剔除 + sprite 物件池
- [ ] 三級縮放（L1/L2/L3）與手勢操作
- [ ] `/api/map` 與 `/api/map/overview`
- [ ] IndexedDB 快取地形 chunk

**驗收**：在手機上流暢平移／縮放整張 500×500 地圖，FPS ≥ 50，
首次載入 < 3 秒。地圖上能看到三座遺跡與自己的出生位置。
以 600 名模擬玩家跑分配，五項公平性驗證全數通過，且總耗時 < 60 秒。

## 相依關係

```
M0 ──┬─→ M1 ──┐
     └─→ M2 ──┴─→ M3 ──→ M3b ──┬─→ M4 ──→ M4b ──┐
                                └─→ M5 ──┬─ M5b ─┤
                                          ├─ M5c ─┤
                                          └─ M5d ─┴─→ M6 ──→ M7
```

M1（地圖）與 M2（經濟）可並行。
M5b（登記輪替）、M5c（AI）、M5d（遺跡軍團）在 M5 之後可並行。

M3（戰鬥）是關鍵路徑上風險最高的一段，建議先做戰鬥引擎的純函式與單元測試，
再接 UI。

**不可延後到 M6 的兩項**：

- **M5c（AI）**：AI 是 600 人密度的前提，而密度決定整個賽季弧線
- **M5d（遺跡軍團）**：它是「用兵高峰在秋冬」的主要引擎。
  沒有它，秋冬的戰鬥量驗證（`16` §10）根本跑不出來

**M3b（補給與區域容量）緊接 M3**：戰鬥引擎與容量機制是耦合的，
分開驗證會漏掉超限損兵與戰鬥結算的交互。
