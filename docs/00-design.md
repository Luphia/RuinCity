# RuinCity · 千年之後 —— 設計文件

> 把地球依經緯度切成區塊，用捐款請 AI 畫出每一塊在**人類離開一千年後**的樣子。
> 從臺北 101 開始。哪一塊先蓋好、由哪一家模型來畫，取決於捐款的人。

本文件是規格。程式碼與它不一致時以本文件為準，並同時修正兩邊。

---

## 1. 世界與網格

| 項目 | 規則 | 實作 |
| --- | --- | --- |
| 區塊大小 | **0.01° × 0.01°**（全球 18,000 列 × 36,000 欄） | `lib/world/grid.ts` |
| 名字 | 西南角兩位小數：`25.03_121.56` = 北緯 25.03°–25.04°、東經 121.56°–121.57° | `blockKey` / `parseBlockKey` |
| 原點 | 臺北 101（25.033964, 121.564468）所在的 `25.03_121.56` | `TAIPEI_101`、`ORIGIN_BLOCK` |
| 實際大小 | 隨緯度變：臺北約 1.01 km（東西）× 1.11 km（南北）；赤道 1.11 × 1.11；北緯 60° 0.56 × 1.11 | `blockSizeM` |

**為什麼是經緯度而不是公尺網格**：公尺網格要選投影，而任何投影都只在一個區域內是方的。
經緯度在全球是同一套規則，任何人拿到一個座標都算得出它屬於哪一塊。
代價是區塊大小隨緯度變化 —— 「一塊」是**命名與募款的單位**，不是測量單位。

**整數索引**：`25.03 × 100` 在浮點數是 `2502.9999…`。所有比較都在整數的列/欄上做，
否則剛好落在格線上的西南角（也就是每一塊自己的名字）會被分到隔壁。

極區（|緯度| > 85°）不開放捐款。

## 2. 一塊地圖的一生

### 2.1 狀態

```
尚無捐款 ──第一筆捐款入帳──▶ 建設中 ⇄ 募款中 ──最後一步完成──▶ 已完成（可進入）
                              │
                              └──連續失敗──▶ 施工暫停
```

| 狀態 | 條件（**由帳推導**，不存欄位） |
| --- | --- |
| 尚無捐款 | 沒有任何已入帳的捐款 |
| 募款中 | 施工餘額不夠下一步估價的 1.25 倍 |
| 建設中 | 正在畫，或餘額夠開下一步 |
| 施工暫停 | 連續失敗 3 次，或平台金鑰被拒（等人處理；新捐款入帳不會自動解除，除非暫停原因是等錢） |
| 已完成 | 所有步驟成功；撥付保存費後標記 |

狀態只存兩個事件：`completed_at` 與 `paused_at`。其餘全部由帳推導 ——
狀態欄位會和帳分岔，而帳才是真相。

### 2.2 完成前不能進入

施工中的區塊**只公開四個數字**：

| 數字 | 定義 |
| --- | --- |
| **預計所需 Token** | 建設各步驟的 token：已完成的取實際、剩下的以目前領先的模型估計 |
| **換算金額** | 完成這一塊所需的**募款總額**（含預算書的全部五組支出） |
| **已花費 Token** | 實際用掉的 token（含失敗重來的） |
| **已花費金額** | 實際花掉的錢：token、參考影像、手續費、稅、拒付準備、完工時撥付的保存與分攤 |

另外公開：募款進度、施工進度（第幾步／共幾步、下一步是什麼）、投票結果、預算書、施工紀錄（哪一步由哪個模型畫、用了多少 token 與錢）。**不公開任何一張圖。**

這個限制守在**出圖的 API**（`/api/blocks/[key]/art/...` 未完成回 403），不只是頁面不顯示 ——
圖的網址是猜得到的。

### 2.3 施工步驟

| # | 步驟 | 產出 | 誰能做 |
| --- | --- | --- | --- |
| 1 | 勘查 SURVEY | 塊內 10×10 個點查 Street View metadata，選出最多 **100 個標記座標** | 不需要模型（免費） |
| 2 | 地圖參數 PARAMS | JSON：地貌、水位、植被密度、殘骸狀態、色調、地標、**8 種材質**、每個標記的一句說明、勘查筆記 | 勘查員（Claude，沒有就 Gemini；不投票） |
| 3 | 標記座標場景圖 SCENE × k | 每個標記一張 16:9 的**紀實照片**，以該點街景為構圖 | 票選的影像模型 |
| 4 | 正射地圖底圖 TILE | **航測正射影像**：俯視、北朝上、剛好框住這一塊；世界地圖上看到的就是它 | 同上 |
| 5 | 3D 圖資 DSM | 與底圖對齊的灰階高度圖（黑＝最低、白＝最高） | 同上 |
| 6 | 材質貼圖 TEXTURE × 8 | 參數列出的 8 種材質，各一張可平鋪的**掃描式 PBR 貼圖** | 同上 |

- **標記座標的選法**：只留塊內的全景、同一全景只算一次、從中心開始做 farthest-point 讓標記散開、
  鏡頭朝向塊中心。全景不到 100 個時，同一個全景轉 90°、180°、270° 再取，最多四個方向。
  沒有街景的地方（山區、海面）k = 0，只畫底圖、3D 與材質。
- **參數排在最前面**：一百張圖可能出自兩家模型，參數是它們共同的「這裡長什麼樣」。
  模型回的 JSON 格式不對時**修正而不是拒絕**（夾回範圍、補足材質與標記說明）；完全解析不了就用預設值 ——
  施工不能卡死在第二步。
- **3D 用高度圖，不用網格模型**：影像模型畫得出灰階高度圖，畫不出可靠的 mesh；
  「正射底圖 + 對齊的高度圖」本來就是地圖做 3D 地景的標準做法（2.5D）。網站與場景包的檢視器用同一份無相依的 WebGL 程式疊成 3D（§10.1）。
- **接縫**：畫底圖時，已完成的鄰塊（北東南西）底圖會一起送給模型，要求邊界上的河流、海岸線、道路延續。

### 2.4 施工引擎

`lib/server/builder.ts`。一次做一步：

1. 拿**租約**（有期限，不抱交易鎖 —— 一步要呼叫外部 API 幾十秒；工作者當掉，租約逾時自動失效）
2. 讀狀態（和頁面看到的是**同一份**推導 `lib/server/blocks.ts`）
3. 沒有下一步 → 撥付保存費與分攤、標記完成
4. 施工餘額 < 下一步估價 × 1.25 → 等錢
5. **此刻**排名最前、做得了這一步的模型 → 畫
6. 成功失敗都記一列 `steps`（帳由它加總）；成功的話正規化成 WebP 存進 `artifacts`

觸發：捐款入帳時用 `after()` 立刻在背景開工；排程（Vercel Cron 每分鐘 `/api/cron/build`、
自架用 `pnpm worker`）是安全網，輪流替每一塊做一步，避免一塊大工程卡住其他小額捐款的區塊。

失敗處理：失敗的那一次**照樣記帳**（上游可能已經收了輸入 token，參考影像也已經抓了）。
連續失敗 3 次暫停；金鑰被拒立刻暫停（那是平台的問題，不會自己好）。

## 3. 捐款

### 3.1 流程

```
捐款人在區塊頁填金額、選模型（可不選）、留言（可不留）
  → POST /api/blocks/[key]/donate        建立 PENDING 捐款，取得金流商付款頁
  → 金流商付款頁
  → 金流商 webhook /api/payments/[processor]/webhook   驗簽 → 入帳（拆帳）→ 背景開工
```

- **入帳只認 webhook**（驗簽之後），不認瀏覽器導回來的那一頁 —— 導回頁可以被偽造。
- 入帳是**冪等**的：金流商重送同一個通知，帳不會記兩次。
- webhook 回報的金額與訂單不符就拒收。
- 單筆最少 NT$30（再少的話手續費會比捐款還多），最多 NT$100,000。
- 已完成的區塊不再收捐款。

### 3.2 拆帳

```
總額 − 金流手續費（金流商回報的實際值；沒有就以費率估）
     − 稅金與規費（總額 × 稅率）
     − 退款與拒付準備（總額 × 準備率）
     = 淨額
```

捐款以新台幣收、成本以美元計。每一筆入帳時存下**當時的匯率**，之後匯率變了，過去的帳不變。
所有金額在資料庫裡是**微美元整數**（1 USD = 1,000,000）—— 捐款帳上不能有浮點誤差。

### 3.3 給 AI 的建議（留言）

每筆捐款可以附一句 ≤140 字的建議（例：「請讓河邊多幾隻白鷺」）。最近 5 則會放進該區塊之後每一步的提示詞。

留言是**不受信任的輸入**：它被放在世界觀正典**之後**、明確標成「建議」，並要求與規則衝突時忽略；
控制字元與換行拿掉、長度截斷、數量設上限 —— 一則留言不能變成一整段新的提示詞。

> 這是原始需求「透過對話要求 AI 調整」在捐款模式下的形式：施工中的地圖看不到，
> 所以無法對著圖來回對話；改成捐款人留下建議，AI 在後續步驟參考。

### 3.4 金流商：**待營運方決定**

目前只實作了**示範金流**（`PAYMENTS=demo`：按一下就當作付款成功，不收錢；網站上方會一直掛著示範模式橫幅）。
示範金流走的是和真實金流**同一條路**（付款頁 → 帶簽章的通知 → 驗簽 → 入帳），
接上真的金流商只需要實作 `lib/payments/types.ts` 的 `PaymentProvider`：

| 方法 | 做什麼 |
| --- | --- |
| `createCheckout` | 建立訂單，回傳付款頁網址與金流商訂單編號 |
| `verifyWebhook` | 驗簽、取出訂單編號、金額、**實際手續費** |

台灣常見選項：綠界 ECPay、藍新 NewebPay、TapPay。Stripe 的支援國家清單在撰寫時不含台灣（以其官方清單為準）。

## 4. 投票：依捐款金額加權

| 規則 | 理由 |
| --- | --- |
| **一筆捐款就是一張選票**，權重 = 那一筆的總額（扣手續費前） | 「依捐款金額比例」最直接的實作 |
| 捐款可以**不投票**；不投票的錢照樣施工，只是不參與決定 | 需求明訂 |
| 捐款人之後可以把自己在某一塊的**所有**捐款改投或撤回，但只在完工前 | 票只在施工期間有意義 |
| **每一張圖開工那一刻**計票 | 因此施工途中只要票數翻盤，下一張就換模型 —— 同一塊裡有兩家的筆觸，是設計的一部分 |
| **只有擬真影像模型能被投**（`PAINTERS`） | 畫面必須擬真（§6.1）。畫不出照片的模型就算票數最高也不該拿到畫筆 |
| 「地圖參數」不投票，由勘查員寫 | 它只產出 JSON，不出現在畫面上；交給最擅長讀圖寫設定的模型 |
| 同票依固定順位：Google → OpenAI | 公開、可預測，不是隨機 |
| 沒有任何有效的票 → 平台預設（`DEFAULT_PROVIDER`） | — |
| 投給**停用中**那一家的票照樣顯示，但不能贏 | 把它從畫面上拿掉，捐款人會以為票不見了 |

每一步都記下開工時的排名快照（`steps.tally`）—— 「這一步為什麼是它畫的」永遠查得到。

投票面板對每一家顯示「若之後全部由它來畫，完成這一塊約需募得 NT$…」，讓捐款人知道選擇的代價
（兩家的總額相近，差別主要在畫風與細節）。

### 4.1 模型與角色

| 公司 | 模型 | 角色 | 可被投票 |
| --- | --- | --- | --- |
| Google | Gemini 3.1 Flash Image（`gemini-3.1-flash-image-preview`） | 畫師（擬真影像）；沒有 Claude 時兼任勘查員 | ✓ |
| OpenAI | GPT Image 2（`gpt-image-2`） | 畫師（擬真影像） | ✓ |
| Anthropic | Claude Opus 5.5（`claude-opus-5-5`） | **勘查員**：讀衛星影像與街景，寫地圖參數 JSON | ✗ |

- Claude 不輸出點陣影像，所以不當畫師（早期版本讓它畫 SVG 向量插畫，違反擬真要求，已移除）。
  它做的那一步決定了一百多張圖要對齊的設定：水位、植被、地標、每個標記點的說明、材質清單。
- 兩家勘查員都沒有金鑰時，地圖參數用預設值（不花錢），施工照常往下走。
- Claude 開啟伺服器端 fallback（`fallbacks: "default"`）：安全分類器誤擋時由另一個模型接手，
  帳記在**實際服務的模型**身上。
- 平台設了哪一家的金鑰，哪一家才啟用（`GEMINI_API_KEY`、`OPENAI_API_KEY`、`ANTHROPIC_API_KEY`）。
- 投票改版前投給 Anthropic 的票，migration `0001` 一律改為「不投票」：錢照樣施工，只是不參與決定。

## 5. 預算書

每一塊都有一份預算書（`lib/world/budget.ts`），每一行寫明算法。各行加總 = 換算金額（募款總額）。

### 5.1 五組支出

| 組 | 項目 | 依據 | 預設參數 |
| --- | --- | --- | --- |
| **建設（Token）** | 地圖參數 | 該步 token × 模型費率 | — |
| | 標記座標場景圖 ×100 | 同上 | — |
| | 正射地圖底圖 | 同上 | — |
| | 3D 圖資（高度圖） | 同上 | — |
| | 材質貼圖 ×8 | 同上 | — |
| **參考資料** | 參考影像費 | Street View 每千張 US$7、地圖靜態圖每千張 US$2；metadata 免費 | — |
| **預備** | 失敗重試準備 | 剩餘 token 成本 × 比例 | 10% |
| | 匯率與價格波動緩衝 | 剩餘建設成本 × 比例 | 5% |
| **保存與營運** | 地圖資料 4 年保存 | 容量（站內 + SwarmStorage 副本）× 48 個月 × **AWS S3** 單價 ＋ 請求 ＋ 傳輸 ＋ 委託手續費 = 筆數 × gas × **Ethereum 主網** gas 單價 × ETH 匯率（§5.5） | 1 + 3 份、US$0.023/GB‧月、PUT US$0.005／GET US$0.0004 每千次、傳輸 US$0.09/GB、2,000 次瀏覽 × 5 MB × 30 次讀取；650k gas × 1.5 gwei × US$2,500/ETH |
| | 伺服器運算與資料庫分攤 | 每塊固定 | US$0.25 |
| | 平台管理費 | 以上合計 × 比例 | **0%**（不抽成） |
| **收款成本** | 金流手續費 | 總額 × 費率 + 每筆固定費（含電子收據） | 2.8% + NT$5 |
| | 稅金與規費 | 總額 × 稅率 | 5%（營業稅） |
| | 退款與拒付準備 | 總額 × 比例 | 1% |

所有參數可用環境變數覆寫（`lib/server/config.ts`，見 `.env.example`）。
不合理的值（負數、比率 ≥ 100%）會被忽略、退回預設 —— 一個打錯的環境變數不該讓預算書變成 NaN。

### 5.2 補齊的項目與理由

需求列出的是：金流手續費、法定稅金或規費、地圖資料 4 年保存、100 張場景圖、3D 圖資、材質貼圖、其他地圖參數。
另外補上：

| 補上的 | 為什麼必須有 |
| --- | --- |
| **正射地圖底圖** | 地圖本身。沒有它，世界地圖上沒有東西可貼；3D 也沒有顏色 |
| **參考影像費** | 每張場景圖都要抓一張街景，是真的要付給 Google 的錢 |
| **失敗重試準備** | 被擋、截斷、沒回圖的那一次照樣計費 |
| **匯率與價格波動緩衝** | 成本是美元、捐款是台幣；模型也可能在施工期間調價 |
| **退款與拒付準備** | 信用卡爭議款與誤捐退款 |
| **伺服器運算與資料庫分攤** | 施工排程、影像轉檔、帳務與四年的資料庫保存 |
| **平台管理費（0%）** | 明列為 0，讓「捐款全數用在這一塊」是一個看得到的承諾，而不是沒寫 |

### 5.3 算法上的幾個決定

- **收款成本倒推（gross-up）**：淨額需要 X，總額得募到 `(X + 筆數 × 固定費) ÷ (1 − 手續費率 − 稅率 − 準備率)`；
  筆數依平均每筆金額（預設 NT$300）估，迭代收斂。已收的部分以實際扣款為準。
- **預備只對還沒做的步驟提列**：已完成的步驟沒有不確定性。失敗掉的實際花費列在「失敗重試準備」的實際欄，不重複算進建設行。
- **保存與分攤先圈存**：捐款淨額先圈出這兩筆（金額很小），剩下才是施工餘額；完工時一次撥入保存基金。
- **結餘**：超募時多的錢列為「預計結餘」，**不算進換算金額** —— 否則捐得愈多「所需」就愈高。完工後保留在該區塊帳上，作為日後整修或延長保存之用。
- **估計會愈來愈準**：同一個模型、同一種步驟累積 3 筆以上實際紀錄後，估計改用實際平均取代表上的先驗。

### 5.4 參考數字（臺北 101 那一塊，100 個標記座標）

| 全部由 | 預計所需 Token | 換算金額 |
| --- | --- | --- |
| Google · Gemini（參數由 Claude） | ≈ 42 萬 | ≈ NT$482 |
| OpenAI · GPT Image（參數由 Claude） | ≈ 49 萬 | ≈ NT$488 |

其中 4 年保存約 NT$113（淨額，收款成本另計）：容量 NT$4.9、請求 NT$0.8、傳輸 NT$28.8、**委託手續費 NT$78**。
手續費是最大的一項 —— 以 Ethereum 主網的 gas 價格估一筆 650k gas 的交易，約 US$2.4。

### 5.5 ★ 保存費的參考價

BOLT 還沒有市價，SwarmStorage 的費用沒辦法「照實際行情」估。所以每一項都找一個公開、常見、查得到的參考價：

| 項目 | 參考 | 預設值（查核日 2026-10-09） | 理由 |
| --- | --- | --- | --- |
| 容量 | **AWS S3 Standard**（us-east-1，前 50 TB） | US$0.023 / GB‧月 | 物件儲存的業界基準。站內副本與 SwarmStorage 的每一個副本都以它計：一份保存就值一份 S3 |
| 寫入／讀取 | S3 PUT／GET | US$0.005 ／ US$0.0004 每千次 | 每個檔案每份寫入一次；每次瀏覽約 30 次讀取 |
| 傳輸 | S3 對外傳輸（前 10 TB） | US$0.09 / GB | 2,000 次瀏覽 × 5 MB |
| 委託手續費 | **Ethereum 主網 gas** | 1.5 gwei × US$2,500 / ETH | Boltchain 相容 EVM，`createDeal` 就是一筆合約呼叫。gas **用量**是在本機 Boltchain devnet 實測的（3 個副本 578k–604k，取 650k）；gas **單價**取 Ethereum 主網（Etherscan 2026-10-07～08 平均 1.3–1.9 gwei） |

連帶的設計：

- **出價也照 S3 parity**：送上鏈的單價（BOLT / GiB / epoch）預設由 S3 換算 ——
  `US$0.023 × GiB/GB × epoch 長度 / 一個月 ÷ BOLT_USD`，讓每個保存者每個 epoch 拿到的，等於同樣容量放在 S3 同樣時間的價格。
  `BOLT_USD` 只在這一步用到（把美元換成 BOLT 出價）；也可以直接設 `SWARM_PRICE_BOLT` 蓋過。
- **epoch 長度決定手續費**：一筆委託最多 3,650 個 epoch。預設以 Boltchain 主網的一天一個 epoch 計 → 四年一筆。
  若在公開測試網（一小時一個 epoch）保存，四年要接力 10 筆，手續費變成 NT$780 —— 比整塊的繪製成本還高。
  這也是預設值選主網的原因；在測試網營運時要把 `SWARM_EPOCH_SECONDS` 改成 3600，並接受這個代價。
- **實際花費以 BOLT 支付**：Boltchain 的 gas 與託管款都是 BOLT。參考價是「為了估多少」，不是「實際付多少」；
  兩者的差額留在該塊的保存基金。

（價格為 2026-10-09 查核的第三方彙整，見 §7。）

## 6. 世界觀與一致性

`lib/world/bible.ts`（`BIBLE_VERSION` = 2）。每一次繪製都放在提示詞最前面（英文，模型對英文的遵從度較好）：

- 人類在一千年前離開，原因不明；植物收復一切（濕熱地區：榕樹氣根、樹蕨、竹、藤蔓、苔）
- **大樓多半還站著**，只剩風化的混凝土外殼：沒有一片玻璃、窗口是黑洞、雨痕與鏽斑、植物從樓板長出來；矮房子多已坍成長滿樹的土丘。**天際線要認得出來**
- 街道與廣場長成草原與幼林；積水成塘；低地淹成沼澤與淺湖；海平面略高；橋只剩橋墩或斷跨
- 野生動物自然地出現、比例正確（鳥、鷺、鹿、獼猴、野豬，也可以有大型草食動物）
- **禁止**：人、可讀的文字、標誌、浮水印、完好的車輛、任何仍在運作的東西
- **地理要認得出來**：同樣的河、海岸線、山與街道格局
- 距臺北 101 六公里內加上地標正典：101 仍然站著、塔尖斷落，玻璃帷幕全部脫落，露出八根巨柱、核心筒與層層「節」的框架

正典改版要 bump `BIBLE_VERSION`；每一步都記下用的版本。

一致性的三層：正典（全世界共用）→ 地圖參數（同一塊共用）→ 鄰塊底圖（接縫）。

### 6.1 ★ 畫面必須擬真

「Photorealistic」一個字不夠 —— 模型對它的理解會從照片一路滑到「很精緻的概念圖」。
所以風格規格寫的是**相機與光線**（照片才有、插畫沒有的東西），再明確列出不要的樣子：

| 產出 | 規格（`bible.ts`） |
| --- | --- |
| 共通 `STYLE_PHOTO` | 與現場拍攝、未經修飾的照片無法分辨；物理上合理的光線、比例、材質與風化；真實的景深與遠處的大氣霧化 |
| 場景 `STYLE_SCENE` | 全片幅相機、24–35 mm、人眼高度、水平線水平；柔和的自然光（多半是陰天或薄霧）；低飽和的自然色；看得到單片葉子、水面倒影、苔與裂縫 |
| 底圖 `STYLE_TILE` | 航測正射影像，約 0.5 m／像素；正上方、北朝上、無透視；均勻的正午光；沒有雲與雲影、沒有任何符號 |
| 材質 `STYLE_TEXTURE` | 攝影測量掃描的 PBR albedo，約 2 m × 2 m；平光、無陰影、無高光、無暗角 |
| 不要 `STYLE_NEGATIVE` | 繪畫、插畫、數位藝術、概念圖、動漫、卡通、遊戲或 3D 算圖感、奇幻元素、過飽和或 HDR、發光、聖光、鏡頭眩光、暗角、文字、浮水印 |

連帶的改變：

- **只有畫得出照片的模型能被投**（§4.1）
- **版型參考改用今天的衛星影像**（`maptype=satellite`），不再是配色過的道路圖 ——
  給模型一張道路圖，它會連那套配色與線條一起「轉繪」出來，畫不出航照
- 3D 高度圖不套擬真規格：它是資料，不是照片
- 示範模式（`FAKE_PROVIDERS=1`）的假圖**不是**擬真的，只是讓流程跑得動，畫面上有「示範模式」標記

使用者提供的參考畫面是一款商業遊戲的截圖。它的**特質**（陰天的柔光、還站著但被掏空的高樓、
淹水的草原與野生動物、低飽和的綠與灰）寫進了上面的文字規格；**圖本身不存、不送給模型** ——
那是受著作權保護的畫面，拿它當每一張圖的風格參考等於要模型臨摹它。

## 10. 永久保存：場景包 × Boltchain SwarmStorage

需求：每一塊地圖資料透過 IPFS 保存，**任何人**都能透過 IPFS 內容重建**一模一樣**的場景；
儲存方案使用 [Boltchain](https://github.com/Luphia/Boltchain) 的 SwarmStorage。

### 10.1 「一模一樣」的定義與三個前提

AI 繪製不可重現：同一個提示詞畫兩次是兩張圖。所以「重建」指的是**用當初畫出來的成品重建場景**，不是重新畫一次。
做得到一模一樣，靠三件事：

| 前提 | 做法 |
| --- | --- |
| **成品原封不動** | 包裡的圖就是資料庫裡的那批位元組（網站出的也是它們），不重新編碼 |
| **怎麼畫寫在包裡** | `scene.json` 的 `render` 是 3D 的完整規格（網格段數、高度比例、相機、光線）。檢視器只照它畫，不讀自己的預設值 |
| **檢視器跟著包走** | 每一包都帶著發布當下的 `index.html` + `viewer.js`（約 25 KB、無相依、CSP 只允許同源）。網站上的 3D 用的是**同一份**渲染程式（`lib/scene/terrain-gl.ts`）。IPFS 依內容去重，一萬包裡同一版檢視器只佔一份空間 |

3D 原本用 three.js；為了讓檢視器能放進「永久保存」的包裡，改寫成約 400 行無相依的 WebGL。

### 10.2 場景包

```
<根 CID>/
  index.html  viewer.js        獨立檢視器
  scene.json                   清單：座標、地圖參數、渲染規格、繪製者、施工紀錄，與其他每個檔案的 SHA-256
  README.txt                   授權、怎麼取回、怎麼打開、怎麼驗證
  map/tile.webp  map/dsm.webp  正射底圖、高度圖
  scenes/000.webp …            標記座標場景圖
  textures/0.webp …            材質貼圖
```

- **決定性**：UnixFS 以 IPIP-499 的 `unixfs-v1-2025` 設定打包（CIDv1、raw leaves、1 MiB 分塊、每節點最多 1024 個連結），每一項都明寫、不依賴函式庫預設；沒有 mtime、沒有 mode。`scene.json` 是正規化 JSON（鍵排序、固定縮排）。同樣的檔案不論順序，永遠是同一個根 CID。
- **任何人都能重算 CID**：`ipfs add -r --only-hash --cid-version=1 --raw-leaves --chunker=size-1048576 <資料夾>`（CI 的 `scene-kubo` 工作用真的 Kubo 比對）。
- **附檔凍結**：`scene.json`、檢視器、README 在第一次打包時存進 `scene_files`，之後只讀不寫。網站之後改了清單欄位或檢視器，已發布的包仍重建得出同一個 CID。
- **付錢之前先驗證**：第一次打包時把區塊拆回檔案、逐一比對；每次要開新委託都重新打包並與記下的 CID 比對 —— 對不上就停下來報錯，不付錢保存一份不一樣的東西。
- **授權：CC0 1.0**。`scene.json` 的 `license` 寫明 `CC0-1.0`、名稱、網址與放棄聲明，README 與檢視器的頁尾也顯示。
  範圍是整個資料夾（圖、地圖參數、文字與檢視器）：任何人都可以複製、修改、散布與商業使用，不需要徵求同意。
  「任何人都能重建」要成立，不只要技術上拿得到，還要法律上被允許 —— 所以授權跟著每一份副本走。
- **不放進包裡的**：Street View 與衛星參考影像（條款不允許保存，§7 #1）。清單只記拍攝年月。

### 10.3 為什麼不加密

Boltchain 的 `storage put` 會用 bolt-vault 加密（只有委託者能解），那是給私人檔案的。
完成的地圖本來就公開，加密了就沒有人能重建 —— 所以場景包以**明文**的 IPLD 區塊交給 SwarmStorage。
合約與抽查只看區塊、不在乎內容是不是密文（Boltchain ADR 0014 §4）。代價見 §7 #9。

### 10.4 SwarmStorage 委託

| 步驟 | 做法 |
| --- | --- |
| 委託索引 | dag-cbor：`{v: 1, size, count, groups, root}`；分組列出場景包 DAG 的**每一個**區塊，`root` = 場景包 CID。編碼與 Boltchain 的 Rust 實作（`bolt-ipld` 的 `deal_index`）**逐位元組相同**（測試釘住了由 Rust 算出的向量） |
| 交給節點 | `bolt_hostBlocks(索引, [[cid, bytes], …])` 到**平台自己的** Boltchain 節點（`--rpc-storage`，RPC 只綁內網）；每批 ≤ 3 MiB |
| 送出委託 | `SwarmStorage.createDeal(索引 CID, 區塊數, 位元組, 副本數, epoch 數, 單價)`，託管款 = `ceil(單價 × MiB / 1024) × 副本 × epoch`（與合約同一個算式）；單價預設是 S3 parity（§5.5）。先模擬、再以 **2 倍 gas** 送出 —— 合約用 `prevrandao` 抽保存者，估 gas 的那一塊與上鏈的那一塊重抽次數不同，照估計值送會 out of gas（本機 devnet 實測） |
| 確認 | 讀交易收據的 `DealCreated` → 委託編號、起訖 epoch；之後每小時讀一次 `dealSlots`（各副本是誰、是否在線） |
| 接力 | 一筆委託的**總長**上限 3,650 個 epoch（`extendDeal` 也不能超過）。主網一天一個 epoch，四年一筆就夠；測試網 1 小時一個 epoch，四年 ≈ 35,064 個 → **10 筆接力的委託**，同一個委託索引，前一筆剩一天時開下一筆（重新交給節點，讓新保存者有地方取資料） |
| 失敗 | 沒有提供者（`NoProviders`）、交易回退等：記在 `scene_archives.last_error`，15 分鐘後重試，畫面上看得到 |

設定（`lib/swarm/registry.ts`）：`BOLT_RPC_URL`、`BOLT_STORAGE_RPC_URL`、`BOLT_PRIVATE_KEY`、`BOLT_CHAIN_ID`、`BOLT_GATEWAYS`；
都沒設時只打包、不上鏈（CID 照算，整包照樣能下載與驗證）；示範模式（`FAKE_PROVIDERS=1` 或 `SWARM_MODE=demo`）走完整條流程但不上鏈，畫面會標明。

### 10.5 任何人怎麼取回與重建

| 管道 | 做法 |
| --- | --- |
| 任何 Boltchain 節點的閘道 | `GET /ipfs/<委託索引 CID>?format=car`。閘道匯出 CAR 時只跟隨 dag-cbor 的連結（不懂 UnixFS），但委託索引的分組正是 dag-cbor 的 CID 清單 —— 所以這個 CAR 含整包 |
| Bitswap | Boltchain 的 Bitswap 與 Kubo／Helia 相容；直接連上一個 Boltchain 節點（它不在公共 IPFS DHT 上）即可 `ipfs get <場景包 CID>` |
| 這個網站 | `/api/blocks/<key>/scene.car`（每次重新打包並比對 CID，對不上就拒絕送出）；`/api/blocks/<key>/scene/index.html` 直接用包裡的檢視器開 |
| 整個世界 | `/api/archive`：每一塊的場景包 CID、委託索引 CID 與生效中的委託編號 |

拿到之後：`pnpm scene:verify <檔案.car | 資料夾> --extract <資料夾>`，或 `--gateway <閘道> <委託索引 CID>`。它檢查每個區塊的雜湊、委託索引列出的區塊都在、
每個檔案符合 `scene.json` 的 SHA-256、**重新打包得到同一個 CID**，然後把資料夾解出來。用任何 HTTP 伺服器打開就是同一個場景
（瀏覽器不允許 `file://` 頁面把圖當 WebGL 貼圖，所以 3D 要經 HTTP）。檢視器打開時也會自己核對每個檔案的 SHA-256 並顯示結果。

### 10.6 已驗證到哪裡

- 在本機起了一條 Boltchain devnet（`genesis/dev.json`：7 位驗證者、`--rpc-storage`、`--gateway`），驗證者 1–3 開放報價。
  網站完工的兩塊各成立一筆真的委託（3 個副本），節點記錄 `keeping deal deal=0 blocks=118`；
  再**只從閘道**取回委託索引的 CAR → `scene:verify` 全部通過、重算得到同一個場景包 CID → 解出的資料夾在瀏覽器裡打開，
  2D、3D 都畫得出來，檢視器顯示「全部 113 個檔案的 SHA-256 都與 scene.json 相符」。
- **沒驗證到的**：抽查（devnet 一個 epoch 是 14,400 塊）、接力委託在真的鏈上換保存者、公開測試網上的報價與 gas。
- Kubo 對同一個資料夾算出相同 CID：本機無法下載 Kubo，交給 CI 的 `scene-kubo` 工作。
