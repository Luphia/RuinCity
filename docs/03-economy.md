# 03 · 資源與經濟

## 1. 五種資源

| 資源 | 代碼 | 主要來源 | 主要用途 | 可否被掠奪 |
| --- | --- | --- | --- | --- |
| 糧食 | `GRAIN` | 農田、主堡基礎產出 | 招兵、**每小時養兵消耗**、前哨營維護 | ✅ |
| 木材 | `TIMBER` | 伐木場 | 所有建築、拓荒隊、攻城單位 | ✅ |
| 石料 | `STONE` | 採石場 | 建築升級、城牆、哨塔 | ✅ |
| 鐵 | `IRON` | 鐵礦坑 | 兵種招募（中高階）、武器科技 | ✅ |
| **遺物** | `RELIC` | 遺跡佔領、廢土營地稀有掉落 | 高階科技、精銳兵種、聯盟科技 | ❌ **永不被掠奪** |

遺物不可掠奪是刻意的：遺物代表「賽季進度」，如果可以被搶，
落後方會被永遠鎖死在落後狀態。遺物只能靠自己打遺跡或清營地取得。

## 2. 產出模型

### 2.1 基礎公式

```
單一設施產出（每小時）
  = 基礎產出(等級)
  × (1 + 地形修正)
  × (1 + 科技加成)
  × (1 + 聯盟遺跡加成)
  × 孤立懲罰（ISOLATED 時 ×0.5）

玩家總產出 = 主堡基礎產出 + Σ 所有領土設施產出 − 養兵消耗 − 前哨營維護
```

基礎產出（每小時）：`10 × level^1.35`（農田／伐木場／採石場），鐵礦坑為 `7 × level^1.35`。

| 等級 | 農田／伐木場／採石場 | 鐵礦坑 |
| --- | --- | --- |
| 1 | 10 | 7 |
| 5 | 43 | 30 |
| 10 | 110 | 77 |
| 15 | 190 | 133 |

主堡基礎產出（不需設施，保底不會餓死）：每種資源 `5 × 主堡等級`/h。

### 2.2 惰性結算（Lazy Accrual）——關鍵技術設計

**不用定時器每秒寫資料庫。** 資源以「快照 + 速率」儲存：

```sql
player_resources(
  player_id,
  grain_amount   NUMERIC,  -- 上次結算時的量
  timber_amount  NUMERIC,
  ...
  grain_rate     NUMERIC,  -- 每小時產出（已扣除消耗，可為負）
  ...
  settled_at     TIMESTAMPTZ  -- 上次結算時間
)
```

讀取時計算：

```
current = clamp(
  amount + rate × (now − settled_at) / 3600,
  0,
  capacity
)
```

只有在**產出速率改變**（蓋建築、升級、兵力變動、領土變動）
或**發生扣款**（招兵、建造、被掠奪）時，才寫入一次資料庫並更新 `settled_at`。

一位玩家平均每天寫入 < 30 次，250,000 格地圖的伺服器成本因此可控。

### 2.3 儲存上限與溢出

| 項目 | 值 |
| --- | --- |
| 基礎上限（每種資源） | 2,000 |
| 倉庫加成 | `+40% × 倉庫等級`（乘算累加） |
| 主堡加成 | `+150 × 主堡等級` |
| 溢出處理 | 超過上限的產出**直接消失**（不入庫，也不通知） |

溢出是這類遊戲讓玩家每天回來的主要機制。
但我們**不做懲罰性溢出**（不扣既有資源），並在介面上顯示「還有 X 小時將溢出」，
讓玩家可以主動規劃，而不是被焦慮驅動。

## 3. 消耗

### 3.1 養兵（糧食）

每個單位每小時消耗糧食，是限制無限爆兵的主要閥門。

| 單位 | 糧耗/h |
| --- | --- |
| 民兵 | 1 |
| 長矛兵 / 劍士 / 弓手 | 1 |
| 掠奪騎兵 | 3 |
| 攻城車 / 投石機 | 4 |
| 精銳單位 | 5 |

**糧食歸零時**：`grain_rate < 0` 且庫存見底 → 每 10 分鐘隨機餓死 3% 的部隊
（優先餓死糧耗最高者）。介面會提前 6 小時紅字警告。

### 3.2 人口上限

```
人口上限 = 50 × 主堡等級^1.15
```

| 主堡等級 | 人口上限 |
| --- | --- |
| 1 | 50 |
| 10 | 706 |
| 20 | 1,570 |
| 30 | 2,532 |

每單位佔用人口：民兵 1、步／弓 1、騎兵 2、攻城 5、精銳 3。

**人口 vs 糧食是雙重限制**：人口決定你「能養多少」，糧食決定你「養不養得起」。
種田流可以糧多但人口不夠（主堡低），攻擊流可以人口高但糧食吃緊。

## 4. 掠奪與保護

### 4.1 地窖 Vault

每位玩家有一個隱藏地窖，**其中的資源永遠不會被掠奪**：

```
地窖保護量（每種資源）= 300 + 80 × 倉庫等級 + 30 × 主堡等級
```

沒蓋倉庫的玩家（Lv1 主堡）保護 330；蓋滿倉庫的玩家可保護 3,000+。
這給了「倉庫」這個核心建築格明確的價值。

### 4.2 掠奪上限

攻方能搶走的量 = `min(部隊總載重, Σ 每種資源的未保護量)`。

各資源按未保護量的比例分攤載重（不會只搶一種）。

| 單位 | 載重 |
| --- | --- |
| 民兵 | 25 |
| 長矛兵 | 40 |
| 劍士 | 50 |
| 弓手 | 35 |
| **掠奪騎兵** | **140** |
| 攻城車 / 投石機 | 0 |

掠奪騎兵載重是劍士的近 3 倍，這讓「劫掠流」成為一個真正可行的資源策略，
而不只是戰鬥策略。

### 4.3 重複劫掠遞減（反霸凌）

```
同一攻方對同一守方，24 小時內第 n 次成功掠奪：
  實際掠奪量 × 0.6^(n-1)
  第 1 次 100%、第 2 次 60%、第 3 次 36%、第 4 次 21.6%…
```

同時，守方連續被同一人打第 3 次後，會收到系統提示與「求援」按鈕，
一鍵發送求援訊息到聯盟頻道（附座標與敵方兵力偵查值）。

## 5. 玩家間交易（集市）

- 需在領土上建 **集市 Market**（每位玩家上限 1 座）
- 掛單：`用 X 數量的 A 資源 換 Y 數量的 B 資源`，設定有效期
- 遺物**不可交易**
- 運輸隊以「商隊」速度（30 格/h）行軍送達，途中可被攔截嗎？→ **v1 不可攔截**
  （攔截機制留 v2，v1 先確保交易系統簡單可靠）
- 交易稅：5% 資源蒸發（回收通膨）
- 同聯盟成員之間交易免稅，鼓勵聯盟內分工

## 6. 經濟曲線目標

| 賽季階段 | 目標主堡等級 | 目標領土數 | 目標兵力（人口） |
| --- | --- | --- | --- |
| 第 3 天 | Lv6–8 | 8–15 | 100–200 |
| 第 1 週 | Lv10–12 | 20–35 | 300–500 |
| 第 3 週 | Lv18–21 | 50–70 | 900–1,400 |
| 第 6 週 | Lv26–30 | 90–120 | 2,000–2,500 |

**設計檢查點**：任何時候，一位「每天上線 3 次、每次 5 分鐘」的休閒玩家，
戰力不應低於「每天上線 10 次」玩家的 50%。
行軍計時制天然壓縮了勤勞度差距——這是選擇這個時間模型的主要理由之一。

## 7. ★ 資源稀缺與強制取捨

這是整份企劃的核心張力。**遊戲的樂趣不在於累積資源，在於決定資源要去哪裡。**

### 7.1 五個競爭中的去向

所有資源最終流向這五處，它們**互相排擠**：

| 去向 | 消耗 | 佔用 | 換到 |
| --- | --- | --- | --- |
| **主堡升級** | 木・石・鐵 | **核心佇列** | 上限（領土容量、人口、建築等級天花板） |
| **核心建築 B/C/D** | 木・石・鐵 | **核心佇列** | 能力（練兵速度、防禦、儲存、攻城） |
| **領土設施** | 木・石 | 領土佇列 | 產出（每小時的資源流） |
| **招募軍隊** | 糧・木・鐵 | 兵營佇列 + **持續糧耗** | 戰力（現在就能用） |
| **拓荒擴張** | 糧・木・民兵 | 領土佇列 | 空間（未來的產出潛力） |

前兩者**共用同一條永不增加的核心佇列**（見 `02` §1.1）——這是最尖銳的一刀。

### 7.2 三道無法迴避的閘門

| 閘門 | 機制 | 造成的取捨 |
| --- | --- | --- |
| **時間** | 核心佇列永遠只有 1 條 | 升主堡 = 不升兵營 |
| **資源** | 成本指數 `1.28^L`，資源不可跨類轉換 | 每一次升級都排擠掉別的升級 |
| **人口** | `50 × 主堡等級^1.15`，且拓荒民兵也佔人口 | 擴張 = 少養兵 |

**資源不可跨類轉換**是刻意的：「我石頭滿了但木頭不夠」是一個真實困境，
唯二的解法是**集市交易（5% 稅）** 或**去搶**。
這讓經濟壓力直接轉化為外交與軍事行為。

### 7.3 第 3 天的十字路口（實例）

假設一位中原帶玩家在 T+72h 手上有 **木 3,200 / 石 2,400 / 鐵 900 / 糧 2,100**，
主堡 Lv6，核心佇列空著。三條路，只能選一條：

| 選擇 | 花費 | 佔用核心佇列 | 第 7 天的你 |
| --- | --- | --- | --- |
| **A · 衝主堡 Lv9** | 木 2,900 / 石 2,400 / 鐵 1,100 | **6 小時** | 領土容量 36、人口 610、建築上限 Lv9。**但幾乎沒有兵**，只能靠新手保護與求鄰居 |
| **B · 兵營 Lv6 + 40 劍士** | 木 1,700 / 石 1,400 / 鐵 4,200 | 3 小時 | 主堡卡 Lv6（容量 24、人口 400），**但你是這一帶最能打的人**，可以靠劫掠養自己 |
| **C · 鋪 8 座領土設施** | 木 3,100 / 石 800 | 0（走領土佇列） | 產出翻倍，主堡與軍隊都沒動。**第 7 天最有錢，第 8 天最容易被搶** |

三條路在第 7 天會長成**三種完全不同的玩家**，
而他們是鄰居——A 需要 B 的保護，B 需要 C 的資源，C 需要 A 的空間。
**取捨產生分工，分工產生聯盟。**

### 7.4 設計檢查：取捨是否真的存在

如果以下任何一項在實測中不成立，代表取捨被稀釋，必須調回：

- [ ] 第 7 天，全服前 20% 玩家的 build（B/C/D 三格組合）**至少出現 5 種不同組合**
- [ ] 第 14 天，主堡等級與總兵力的相關係數 **< 0.6**（若接近 1，代表根本沒有取捨，大家都在做同一件事）
- [ ] 核心佇列的平均閒置率 **< 10%**（若常常空著，代表資源不夠稀缺，或成本太低）
- [ ] 集市的日成交量 **> 全服日產出的 8%**（代表資源不可轉換確實造成了真實的短缺與交易需求）
