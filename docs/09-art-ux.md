# 09 · 美術風格與手機 UI/UX

## 1. 視覺定位

**廢土像素風（Post-apocalyptic pixel art）**。
不是可愛的 8-bit，也不是寫實。參考座標：
《Kenshi》的荒涼 × 《Dwarf Fortress》Tileset 的資訊密度 × 《Loop Hero》的克制色彩。

關鍵字：**鏽蝕、風沙、殘存的秩序、遠方的光**。

## 2. 像素規範

| 項目 | 規範 |
| --- | --- |
| 基準 tile | **32 × 32 px** |
| 資產製作 | 以 32×32 製作，以整數倍縮放呈現（1×/2×/4×） |
| 縮放策略 | `image-rendering: pixelated`；PixiJS `scaleMode: NEAREST`、`roundPixels: true` |
| 允許縮放級距 | 2 / 4 / 8 / 16 / 32 px per tile（**只允許 2 的冪**，避免非整數縮放糊化） |
| 動畫幀數 | 建築閒置 2 幀（0.8s/幀）、單位移動 4 幀、特效 ≤ 6 幀 |
| 圖集 | 單張 2048×2048 texture atlas，含 padding 2px 防止取樣溢出 |
| 描邊 | 建築與單位使用深色 1px 描邊（`#1a1614`），確保在任何地形上都可辨識 |

**遺物金 `#d9a441`** 是整個遊戲最稀有的顏色，只用於遺跡、遺物資源與勝利相關元素。
玩家在地圖上看到金色，就知道那裡有重要的東西。

### 聯盟 15 色

對應 **3 陣營 × 5 聯盟 = 15 個名額**（見 `06` §0）。

**同陣營的 5 色刻意屬於同一色系**（不同明度／彩度），
於是 L3 戰略視圖上一眼就能看出三大勢力範圍，
再放大才分得出是該陣營的哪一個聯盟：

| 陣營 | 色系 | 5 色 |
| --- | --- | --- |
| I 灰燼氏族 | 鏽紅／橙 | `#c4442f` `#e07a3f` `#a8563a` `#d96c8a` `#8c3d2e` |
| II 穹窖商會 | 青／藍 | `#3f9aa3` `#4a72c4` `#2f7f8c` `#4f5fa8` `#6fa8b8` |
| III 鐵搖籃盟 | 綠／黃 | `#7fa832` `#3fa36b` `#9c9c4a` `#d9a441` `#5c8a45` |

已通過紅綠色盲（deuteranopia）與藍黃色盲（tritanopia）模擬檢查：
**跨陣營的任兩色**在模擬後必須可區分；
同陣營內的 5 色只需在 L2（8px）以上可區分——
在 L3 它們本來就該看起來像同一個勢力。

> 這是一個罕見的情況：**視覺限制與遊戲結構恰好對齊**。
> 「2px 下能可靠區分的顏色數量」與「三大勢力各 5 個聯盟」
> 剛好都收斂在 3 × 5 的分組上。

### 聯盟 HEX 代碼的顯示

每個聯盟另有系統配發的 2 位 HEX 代碼（`00`–`FF`，見 `06` §3.4）。
它是 L3 戰略視圖上**唯一讀得出來的識別**：

| 縮放層級 | 聯盟識別方式 |
| --- | --- |
| L3（2px/格） | 顏色 + 滑過／點擊顯示 `[A7]` |
| L2（8px/格） | 顏色 + 領土上疊印 2 字元代碼（5×7 像素字） |
| L1（32px/格） | 顏色 + 完整 `[A7] 鐵鴉商會` 名牌 |

代碼用 **5×7 點陣像素字**，即使在 8px 格子上也清晰可辨。
在遺跡進度環、戰報標題、聯盟排行榜中一律以 `[HEX] 名稱` 格式呈現。

### 主旗與圍城的視覺

斬首機制（`06` §4）是全場最戲劇化的事件，視覺必須壓倒性：

| 元素 | 呈現 |
| --- | --- |
| 主旗據點 | 據點上方永久插一面聯盟旗（2 幀飄動），所有玩家可見 |
| 圍城中 | 該格外圍紅色脈動光環（L1–L3 皆可見）+ 全螢幕頂部紅色橫幅 + 倒數 |
| 全服公告 | 「🚩 [A7] 鐵鴉商會 的主旗正在被 [3C] 灰燼氏族 圍攻 — 01:47:22」 |
| 淪陷 | 該聯盟所有領土在 3 秒內褪色為中性灰（動畫），據點變廢墟貼圖 |

**這是唯一允許使用全螢幕橫幅與強烈動態的場合**（`prefers-reduced-motion`
下改為靜態紅框 + 倒數文字）。其餘時間介面必須保持克制。

## 4. 字體

| 用途 | 字體 |
| --- | --- |
| 數字與英文 | 自製 5×7 點陣像素字（或 `Silkscreen`） |
| **中文** | **Zpix（最像素）** — 12px 基準，支援繁中全字集，開源 |
| 長篇說明文字 | 系統 sans-serif（**刻意不用像素字**） |

**重要決策**：教學、戰報詳情、規則說明等長文**不使用像素字**。
12px 點陣中文在長段落中閱讀負擔極重。像素字用於標題、數值、按鈕，
長文用系統字體並以像素風邊框包裹——風格由框架承擔，可讀性由字體承擔。

## 5. 手機 UI 架構

### 5.1 版面（直式 / 390×844 基準）

```
┌──────────────────────────────┐
│ 狀態列  糧🌾 木🪵 石🪨 鐵⚙ 遺✦ │  40px 常駐（M5c 實作：GameHud，見 §12.2）
├──────────────────────────────┤
│ 遺跡列  ✦I 灰燼[鐵鴉] ✦II … │  28px 常駐，賽季敘事
├──────────────────────────────┤
│                              │
│                              │
│        主內容區               │  地圖 / 據點 / 軍隊 …
│      （PixiJS Canvas          │
│        或 React 面板）        │
│                              │
│                              │
├──────────────────────────────┤
│  🏰   🗺   ⚔   🛡   ☰      │  底部 Tab，56px + safe-area
│ 據點  地圖  軍隊 聯盟  更多    │
└──────────────────────────────┘
```

- **所有主要操作在拇指可及範圍**（螢幕下半 60%）
- 底部 tab 上方預留 `env(safe-area-inset-bottom)`
- 彈出面板一律從**底部滑上**（bottom sheet），不用置中 modal
  ——單手可關閉、符合手機直覺

### 5.2 地圖操作手勢

| 手勢 | 行為 |
| --- | --- |
| 單指拖曳 | 平移 |
| 雙指縮放 | 縮放（吸附到 2 的冪級距，有回彈動畫） |
| 雙擊 | 放大一級 |
| 單擊格子 | 選取，底部滑出資訊卡（誰的、什麼設施、距離、行軍時間） |
| 長按格子 | 直接開啟行動輪盤（攻擊／突襲／偵查／拓荒／增援） |
| 雙指旋轉 | **不支援**（正交網格不需要，且容易誤觸） |

**行動輪盤**：長按後在手指周圍浮現 4–6 個圓形圖示，
手指不放開直接滑向目標圖示後放開即執行。這是手機上最快的操作方式，
比「點擊 → 開面板 → 選項目 → 確認」快 3 倍。

### 5.3 資訊卡（點擊格子後）

```
┌────────────────────────────────┐
│ ▓ 鐵鴉商會 · 廢墟哨站          │
│ (218, 341) · 森林 · 距離 34 格 │
├────────────────────────────────┤
│ 主堡 Lv14   聯盟：鐵鴉商會      │
│ 行軍時間  劍士 1h42m · 騎兵 51m │
├────────────────────────────────┤
│  [偵查]  [突襲]  [攻擊]  [⋯]   │
└────────────────────────────────┘
```

**「行軍時間」直接顯示在資訊卡上**，不需要進入派兵畫面才知道。
在行軍計時制的遊戲裡，時間就是距離，玩家每一次評估目標都在問這個問題。

## 6. 關鍵畫面

| 畫面 | 重點 |
| --- | --- |
| **據點** | 2×2 核心放大顯示，四格可直接點擊升級；下方為建造佇列與招兵佇列 |
| **執政官** | 三個方針的開關與參數、資源保留下限滑桿、暫停按鈕、歷史簡報 |
| **地圖** | 見上 |
| **軍隊** | 上半：進行中的行軍列表（含倒數與召回鈕）；下半：各地駐軍總覽 |
| **聯盟** | 上半：聊天（預設焦點）；下半：成員列表 + 遺跡狀態 |
| **戰報** | 列表 + 詳情。詳情頁**完整展開計算過程**（戰力、士氣、存活率），可展開／收合 |

### 6.0 ★ 施政簡報：登入的第一個畫面

執政官（見 `18`）取代了「一整面待處理通知」的回歸體驗。
登入時看到的不是一堆紅點，是**一位下屬的回報**：

```
┌──────────────────────────────────────────┐
│ 執政官 · 灰喉                              │
│ 廢曆 41 年 3 月 14 日 — 您離開了 9 小時      │
├──────────────────────────────────────────┤
│ ▸ 拓荒 2 格：第 47 區 · 鏽谷 (218,341)      │
│ ▸ 農田 (215,339) 升至 Lv6                  │
│ ▸ 招募 劍士 ×40、長矛兵 ×25                 │
│                                          │
│ ⚠ 領主，糧食將於 4 小時後溢出               │
│ ⚠ 木材保留下限 5,000，本可再拓荒 2 格        │
│                                          │
│ 🗡 期間您遭受 1 次突襲（損失 木 340）        │
│    [ 查看戰報 ]                            │
├──────────────────────────────────────────┤
│        [ 知道了 ]      [ 調整方針 ]         │
└──────────────────────────────────────────┘
```

設計要點：

- **執政官頭像 32×32 像素**，有名字，說話用「領主」稱呼玩家
- **`BLOCKED` 訊息與行動訊息同等重要**——沒做什麼也要說
- 離線 > 24 小時改為**逐日時間軸**，而非單一列表
- 「調整方針」直接跳到執政官頁，讓簡報成為調整的入口

同一份資訊，完全不同的體感。這也是遊戲曆（`14` §2）
與廢土敘事真正落地在每次登入第一秒的地方。

### 6.0b ★ 區域容量必須是一級資訊

補給／區域容量（見 `16`）是這套設計裡**最容易讓玩家困惑**的機制：
部隊莫名減員、糧耗突然暴漲，如果玩家看不懂原因，體驗會極差。

因此它不能是隱藏在數字後面的規則，必須在三個地方**主動顯示**：

| 位置 | 顯示內容 |
| --- | --- |
| **地圖（L2/L3）** | 區域格線與名稱；點擊區域顯示「我方容量 6,250 / 已駐 4,100」的容量條 |
| **派兵確認畫面** | 「抵達後該區將有 5,200 人，超出容量 1,100 人 → 每小時損兵 55」，紅字預警 |
| **戰報與通知** | 減員明確歸因：「第 47 區 · 鏽谷 補給不足，損失 128 人」 |

季節切換前 6 小時的預警也要包含容量變化：
「冬季將至：第 47 區的容量將由 6,250 降為 3,750，你目前駐有 5,100 人」。

**規則可以複雜，但後果必須可預期。** 玩家可以不懂公式，
但不能在打開遊戲時發現三千人不見了卻不知道為什麼。

### 6.1 戰報詳情的設計原則

玩家輸掉一場仗時，最挫折的不是輸，是**不知道為什麼輸**。
戰報必須能回答：

```
你的戰力 12,400
  ├ 基礎攻擊 14,200
  ├ 攻擊科技 +8%    → 15,336
  └ 士氣 ×0.81      → 12,422   ← 因為對方人口只有你的 1/3

對方防禦 15,800
  ├ 基礎防禦 11,900
  ├ 城牆 Lv8 +64%   → 19,516
  ├ 森林地形 +10%   → 21,468
  └ ⚠ 有 3 位盟友增援（+4,900）

結果：防守方勝，你的部隊全滅
```

每一行都可點擊查看該項的計算規則。這是社群信任的基礎，
也大幅減少客服與「這遊戲是不是有 bug」的爭議。

## 7. 效能與省電

| 措施 | 說明 |
| --- | --- |
| 分頁隱藏 | `visibilitychange` → `ticker.stop()`、SSE 5 分鐘後斷線 |
| 閒置降幀 | 無互動 5 秒 → 15fps；有互動立即回 60fps |
| 動畫節制 | 地圖上不做粒子特效、不做光暈；只有選取框與行軍箭頭會動 |
| 圖片 | 全部 PNG-8（256 色以內），符合調色盤限制後檔案極小 |
| 字體 | Zpix 用 `unicode-range` 子集化，只載入常用 3,500 字 |

## 8. PWA 與通知

- `manifest.json`：standalone、直向鎖定、maskable icon
- Service Worker：快取 app shell 與地形 chunk（stale-while-revalidate）
- **Web Push**（需使用者授權）：
  - 據點被攻擊（30 分鐘預警）
  - 行軍抵達
  - 建造／研究完成（可關閉）
  - 遺跡控制權變化（僅聯盟成員）
- 通知有**每小時上限 6 則**，避免變成騷擾

## 9. 無障礙

| 項目 | 措施 |
| --- | --- |
| 色盲 | 聯盟色已通過 deuteranopia 檢查；地圖可開「圖案疊加」模式（不同聯盟用不同斜線紋理） |
| 對比 | UI 文字對背景 ≥ 4.5:1；像素字建議 ≥ 7:1 |
| 觸控目標 | 所有可點元素 ≥ 44×44 px |
| 減少動態 | 尊重 `prefers-reduced-motion`，關閉所有轉場與閒置動畫 |
| 字級 | 提供「大字模式」，UI 文字放大 1.25×（像素字改用 2× 縮放） |

## 10. 本地化

- v1：**繁體中文**（主要）、English
- 所有文案走 i18n key，不寫死在元件中
- 像素字型需確認涵蓋兩種語系；英文用 Silkscreen，中文用 Zpix
- 數字格式化與時間顯示依 locale（`Intl.NumberFormat` / `Intl.RelativeTimeFormat`）

## 11. 渲染實作（M1b）

### 11.1 地形：每個 chunk 一張貼圖，不是一格一個 sprite

500×500 = 250,000 格，而 L3（2px/格）時**整張圖都在畫面上**。
250,000 個 sprite 在手機上光是遍歷就掉到個位數 FPS。

實際做法是把每個 64×64 chunk 烘成一張 **64×64 的貼圖（一格一像素）**，
用一個 sprite 畫出來、放大 `tilePixels` 倍。配上 `NEAREST` 取樣，
放大後每格就是一個銳利的色塊 —— 正是像素風要的效果。

於是整張地圖**永遠只有 64 個 sprite**，再經視野剔除通常只剩 1–9 個。
E2E 有一條測試就在盯這件事：任何縮放層級下 sprite 數都必須 < 200。

實作見 [`lib/render/chunks.ts`](../lib/render/chunks.ts)。

### 11.2 五層

| 層 | 內容 | 備註 |
| --- | --- | --- |
| terrain | 地形色塊 | 每 chunk 一個 sprite |
| territory | 聯盟領土色 | 同樣每 chunk 一個 sprite（M2 接上） |
| structure | 據點、遺跡、營地 | Graphics 物件池，L3 不畫據點 |
| march | 行軍箭頭 | M2 接上 |
| overlay | 區域格線、選取框、名牌 | |

**遺跡在所有層級都畫**，而且在 L3 有最小尺寸 —— 它是地圖上唯一的金色，
`§3` 說「玩家看到金色就知道那裡有重要的東西」，那就不能因為縮太遠而消失。

### 11.3 手勢的兩個細節

- **縮放吸附用對數距離。** 層級是 2 / 8 / 32，等比不等差。
  用線性距離的話 5px 會吸到 2，但幾何中點其實是 4 —— 手感明顯不對。
- **縮放要以手指之間那一點為錨。** 少了它，雙指縮放會從畫面中心脹縮，
  使用者想放大的東西會滑走。這是手機地圖最明顯的手感缺陷。

相機運算全部是純函式（[`lib/render/viewport.ts`](../lib/render/viewport.ts)），
所以這兩件事都有單元測試盯著。

### 11.4 快取

地形層在賽季內永不改變，所以是快取的完美對象：
**記憶體 → IndexedDB → 網路** 三層。64 個 chunk 全下載只有 256 KB，
但在手機網路上仍是好幾秒，第二次進遊戲要能直接從 IndexedDB 讀。

## 12. 對照同類作品的修正（M5c）

拿一款成熟的像素風手機王國遊戲的兩張截圖（據點畫面與世界地圖）
對照我們的畫面，差距不在美術密度，而在三條資訊設計原則。
逐條檢討如下 —— **採用的翻成 RuinCity 的語言，不採用的寫下理由**。

### 12.1 ★ 狀態長在場景上，不是場景旁邊

參考畫面裡，建築的等級是泡泡、施工倒數浮在工地上、
訓練中的單位是螢幕邊緣的浮動小chip。玩家**看一眼城**就知道一切，
不需要往下捲到任何清單。

我們原本的據點頁是「場景 + 一疊 section」：佇列在場景下方的卡片裡，
倒數與場景是分開的兩個世界。修正：

- 施工倒數（🔨 m:ss）疊在**鷹架那塊地**的正上方（`CitadelScene`）
- 進行中的招募佇列浮在場景右緣
- 佇列 section 保留 —— 那是帳本；場景上的倒數是現場

一般化：**佇列是資料庫的 view，場景是玩家的 view** ——
玩家不欠資料庫一次捲動。

### 12.2 ★ HUD 是常駐的一條，不是每頁自己排一個

參考畫面的資源列（值 + 產率 + 儲存量條）在據點與地圖上**一模一樣**。
我們的 §5.1 從 M0 就畫了那條 40px 常駐狀態列 —— 但一直沒實作，
資源條只活在據點頁的一個 section 裡。

修正（`components/hud/GameHud.tsx`）：四種資源（值、時速、儲存量條、
滿倉變紅）、四季色段（荒芽綠→焦土鏽→豐鏽金→長夜藍）、廢曆日期、
人口、以及「**下一件會完成的事**」的倒數。掛在 `(game)` layout，
地圖頁浮在畫布上緣。

- 數字是**外推**的（快照 + 速率 × 間隔，`lib/game/hud.ts`），
  每 60 秒與伺服器對帳，只供顯示 —— P1 不動搖。
- 「下一件完成的事」回答玩家抬頭要問的那個問題：「我什麼時候要回來」。
  全部閒置時**不顯示** —— 閒置是執政官該接手的訊號，不是玩家的待辦。

### 12.3 ★ 地圖是遊戲發生的地方，不只是看的地方

參考畫面的地圖上：領土有描邊、可佔的格子有記號、
部隊是**沿虛線路徑走的人**、據點是真的建築。
我們的地圖在 M5c 之前只有地形 + 出生點 + 遺跡 —— 一張漂亮的死圖。

修正（個人圖層，`app/actions/map.ts` + `lib/render/scene.ts`）：

- **我的領土**沿邊界描一圈生機藍（塗滿會蓋掉地形；描邊讓
  「疆界在長大」看得見）。演算法是純函式（`lib/render/territory.ts`）
- **我的據點**金色框，而且**開圖聚焦在這裡** ——
  之前聚焦在 `spawns[0]`，那是別人的家
- **我的行軍**：虛線路徑 + 沿路徑移動的部隊點。
  進度 = 時間的函數（departedAt→arrivesAt），客戶端只量流逝的間隔
- 交戰標示（脈動紅 ✕ + 觀戰）是 §20.22 先做的，同一條原則

迷霧不變：只畫**自己的**領土與行軍。來襲預警有自己的規則
（`warningVisibleAt`），之後接上時畫成反向的紅色路徑。

### 12.4 戰場士兵：25×25 的六態動畫

士兵從「幾個色塊」升級成 25×25 的程式生成 sprite（`lib/game/soldier.ts`），
四個兵種（步、弓、騎、器械）× 兩陣營 × 六種動畫：

| 動畫 | 什麼時候播 | 表演 |
| --- | --- | --- |
| WALK | 行進與遊走 | 4 幀循環：邁步、身體顛一格；器械是輪輻在轉 |
| ATTACK | 交戰，跟著**攻速節奏** | 出手那一 tick 是第 0 幀：矛刺出／滿弓放箭／馬刀劈下／拋臂擊發 |
| SKILL | 怒氣技那一擊 | 金色殘光（金色只給重要的事，§3）：金矛尖、齊射、人立馬、金石彈 |
| HIT | 這一 tick 掉了血 | 後仰 + 命中閃光 + 一點血 |
| DYING | 血量 ≤ 35% | 跪地拄矛／馬垂頭／器械斷輪傾斜 —— 瀕死取代行進，但不取代攻擊 |
| DEATH | 倒下的過程 | 4 幀：後仰 → 半倒 → 觸地揚塵 → **屍體永久留在原地**（武器掉在旁邊） |

- 動畫選擇是純函式（`pickAnim`，優先序：死亡 > 技能 > 被擊 > 攻擊 > 瀕死 > 行進）。
  畫面層只記「什麼時候發生的」（掉血／放技／倒下的 tick），不做規則判斷。
- 攻擊幀由 `攻速 − cooldown` 推出來 —— 動畫天然與傷害同步，不用另外記時間。
- 所有士兵面向右。陣營靠**顏色**分（攻方鏽紅、守方生機藍），不靠朝向 ——
  25px 小人翻面的辨識收益遠低於快取翻倍的成本。
- 「動畫要動」是可測的性質（§21.2 的同族）：相鄰兩幀必須不同、
  屍體的輪廓必須比活人矮、技能必有金色 —— 全部寫成測試。

### 12.5 不採用的

| 參考畫面的元素 | 不採用的理由 |
| --- | --- |
| 加值貨幣（金幣 + 號）、禮包 | RuinCity 沒有 IAP。賽季制 + 傳承點是唯一的長期激勵（`docs/00`） |
| 任務鏈釘選（「攻佔3塊木頭地 2/3」） | 我們的答案是**執政官** —— 瑣事他做，玩家做決策（P4）。強行加任務鏈會把玩家推回打卡迴圈。賽季敘事目標（遺跡）之後在遺跡列講 |
| 可愛畫風、飽和草地 | 視覺定位是廢土（§1）。參考它的**資訊設計**，不是它的顏色 |
| 可佔格的綠色記號 | 想要，但「哪些格可佔」依賴 M3b 的區域容量與相鄰規則 —— 先把規則做對，再把記號畫上去，不然記號會說謊 |

（§12.4 的士兵動畫是這次對照的延伸：參考作品的單位「活著」——
會走、會打、會倒下 —— 而我們的戰場當時只有會滑動的色塊。）
