# 09 · 美術風格與手機 UI/UX

## 1. 視覺定位

**廢土像素風（Post-apocalyptic pixel art）**。
不是可愛的 8-bit，也不是寫實。參考座標：
《Kenshi》的荒涼 × 《Dwarf Fortress》Tileset 的資訊密度 × 《Loop Hero》的克制色彩。

關鍵字：**鏽蝕、風沙、殘存的秩序、遠方的光**。

## 2. 像素規範

| 項目 | 規範 |
| --- | --- |
| 基準 tile | **32 × 32 px** |
| 資產製作 | 以 32×32 製作，以整數倍縮放呈現（1×/2×/4×） |
| 縮放策略 | `image-rendering: pixelated`；PixiJS `scaleMode: NEAREST`、`roundPixels: true` |
| 允許縮放級距 | 2 / 4 / 8 / 16 / 32 px per tile（**只允許 2 的冪**，避免非整數縮放糊化） |
| 動畫幀數 | 建築閒置 2 幀（0.8s/幀）、單位移動 4 幀、特效 ≤ 6 幀 |
| 圖集 | 單張 2048×2048 texture atlas，含 padding 2px 防止取樣溢出 |
| 描邊 | 建築與單位使用深色 1px 描邊（`#1a1614`），確保在任何地形上都可辨識 |

玩家在地圖上看到金色，就知道那裡有重要的東西。

### 聯盟 15 色

對應 **3 陣營 × 5 聯盟 = 15 個名額**（見 `06` §0）。

**同陣營的 5 色刻意屬於同一色系**（不同明度／彩度），
於是 L3 戰略視圖上一眼就能看出三大勢力範圍，
再放大才分得出是該陣營的哪一個聯盟：

| 陣營 | 色系 | 5 色 |
| --- | --- | --- |
| I 灰燼氏族 | 鏽紅／橙 | `#c4442f` `#e07a3f` `#a8563a` `#d96c8a` `#8c3d2e` |
| II 穹窖商會 | 青／藍 | `#3f9aa3` `#4a72c4` `#2f7f8c` `#4f5fa8` `#6fa8b8` |
| III 鐵搖籃盟 | 綠／黃 | `#7fa832` `#3fa36b` `#9c9c4a` `#d9a441` `#5c8a45` |

已通過紅綠色盲（deuteranopia）與藍黃色盲（tritanopia）模擬檢查：
**跨陣營的任兩色**在模擬後必須可區分；
同陣營內的 5 色只需在 L2（8px）以上可區分——
在 L3 它們本來就該看起來像同一個勢力。

> 這是一個罕見的情況：**視覺限制與遊戲結構恰好對齊**。
> 「2px 下能可靠區分的顏色數量」與「三大勢力各 5 個聯盟」
> 剛好都收斂在 3 × 5 的分組上。

### 聯盟 HEX 代碼的顯示

每個聯盟另有系統配發的 2 位 HEX 代碼（`00`–`FF`，見 `06` §3.4）。
它是 L3 戰略視圖上**唯一讀得出來的識別**：

| 縮放層級 | 聯盟識別方式 |
| --- | --- |
| L3（2px/格） | 顏色 + 滑過／點擊顯示 `[A7]` |
| L2（8px/格） | 顏色 + 領土上疊印 2 字元代碼（5×7 像素字） |
| L1（32px/格） | 顏色 + 完整 `[A7] 鐵鴉商會` 名牌 |

代碼用 **5×7 點陣像素字**，即使在 8px 格子上也清晰可辨。
在遺跡進度環、戰報標題、聯盟排行榜中一律以 `[HEX] 名稱` 格式呈現。

### 主旗與圍城的視覺

斬首機制（`06` §4）是全場最戲劇化的事件，視覺必須壓倒性：

| 元素 | 呈現 |
| --- | --- |
| 主旗據點 | 據點上方永久插一面聯盟旗（2 幀飄動），所有玩家可見 |
| 圍城中 | 該格外圍紅色脈動光環（L1–L3 皆可見）+ 全螢幕頂部紅色橫幅 + 倒數 |
| 全服公告 | 「🚩 [A7] 鐵鴉商會 的主旗正在被 [3C] 灰燼氏族 圍攻 — 01:47:22」 |
| 淪陷 | 該聯盟所有領土在 3 秒內褪色為中性灰（動畫），據點變廢墟貼圖 |

**這是唯一允許使用全螢幕橫幅與強烈動態的場合**（`prefers-reduced-motion`
下改為靜態紅框 + 倒數文字）。其餘時間介面必須保持克制。

## 4. 字體

| 用途 | 字體 |
| --- | --- |
| 數字與英文 | 自製 5×7 點陣像素字（或 `Silkscreen`） |
| **中文** | **Zpix（最像素）** — 12px 基準，支援繁中全字集，開源 |
| 長篇說明文字 | 系統 sans-serif（**刻意不用像素字**） |

**重要決策**：教學、戰報詳情、規則說明等長文**不使用像素字**。
12px 點陣中文在長段落中閱讀負擔極重。像素字用於標題、數值、按鈕，
長文用系統字體並以像素風邊框包裹——風格由框架承擔，可讀性由字體承擔。

## 5. 手機 UI 架構

### 5.1 版面（直式 / 390×844 基準）

```
┌──────────────────────────────┐
│ 狀態列  糧🌾 木🪵 石🪨 鐵⚙ 遺✦ │  40px 常駐，點擊展開產出明細
├──────────────────────────────┤
│ 遺跡列  ✦I 灰燼[鐵鴉] ✦II … │  28px 常駐，賽季敘事
├──────────────────────────────┤
│                              │
│                              │
│        主內容區               │  地圖 / 據點 / 軍隊 …
│      （PixiJS Canvas          │
│        或 React 面板）        │
│                              │
│                              │
├──────────────────────────────┤
│  🏰   🗺   ⚔   🛡   ☰      │  底部 Tab，56px + safe-area
│ 據點  地圖  軍隊 聯盟  更多    │
└──────────────────────────────┘
```

- **所有主要操作在拇指可及範圍**（螢幕下半 60%）
- 底部 tab 上方預留 `env(safe-area-inset-bottom)`
- 彈出面板一律從**底部滑上**（bottom sheet），不用置中 modal
  ——單手可關閉、符合手機直覺

### 5.2 地圖操作手勢

| 手勢 | 行為 |
| --- | --- |
| 單指拖曳 | 平移 |
| 雙指縮放 | 縮放（吸附到 2 的冪級距，有回彈動畫） |
| 雙擊 | 放大一級 |
| 單擊格子 | 選取，底部滑出資訊卡（誰的、什麼設施、距離、行軍時間） |
| 長按格子 | 直接開啟行動輪盤（攻擊／突襲／偵查／拓荒／增援） |
| 雙指旋轉 | **不支援**（正交網格不需要，且容易誤觸） |

**行動輪盤**：長按後在手指周圍浮現 4–6 個圓形圖示，
手指不放開直接滑向目標圖示後放開即執行。這是手機上最快的操作方式，
比「點擊 → 開面板 → 選項目 → 確認」快 3 倍。

### 5.3 資訊卡（點擊格子後）

```
┌────────────────────────────────┐
│ ▓ 鐵鴉商會 · 廢墟哨站          │
│ (218, 341) · 森林 · 距離 34 格 │
├────────────────────────────────┤
│ 主堡 Lv14   聯盟：鐵鴉商會      │
│ 行軍時間  劍士 1h42m · 騎兵 51m │
├────────────────────────────────┤
│  [偵查]  [突襲]  [攻擊]  [⋯]   │
└────────────────────────────────┘
```

**「行軍時間」直接顯示在資訊卡上**，不需要進入派兵畫面才知道。
在行軍計時制的遊戲裡，時間就是距離，玩家每一次評估目標都在問這個問題。

## 6. 關鍵畫面

| 畫面 | 重點 |
| --- | --- |
| **據點** | 2×2 核心放大顯示，四格可直接點擊升級；下方為建造佇列與招兵佇列 |
| **執政官** | 三個方針的開關與參數、資源保留下限滑桿、暫停按鈕、歷史簡報 |
| **地圖** | 見上 |
| **軍隊** | 上半：進行中的行軍列表（含倒數與召回鈕）；下半：各地駐軍總覽 |
| **聯盟** | 上半：聊天（預設焦點）；下半：成員列表 + 遺跡狀態 |
| **戰報** | 列表 + 詳情。詳情頁**完整展開計算過程**（戰力、士氣、存活率），可展開／收合 |

### 6.0 ★ 施政簡報：登入的第一個畫面

執政官（見 `18`）取代了「一整面待處理通知」的回歸體驗。
登入時看到的不是一堆紅點，是**一位下屬的回報**：

```
┌──────────────────────────────────────────┐
│ 執政官 · 灰喉                              │
│ 廢曆 41 年 3 月 14 日 — 您離開了 9 小時      │
├──────────────────────────────────────────┤
│ ▸ 拓荒 2 格：第 47 區 · 鏽谷 (218,341)      │
│ ▸ 農田 (215,339) 升至 Lv6                  │
│ ▸ 招募 劍士 ×40、長矛兵 ×25                 │
│                                          │
│ ⚠ 領主，糧食將於 4 小時後溢出               │
│ ⚠ 木材保留下限 5,000，本可再拓荒 2 格        │
│                                          │
│ 🗡 期間您遭受 1 次突襲（損失 木 340）        │
│    [ 查看戰報 ]                            │
├──────────────────────────────────────────┤
│        [ 知道了 ]      [ 調整方針 ]         │
└──────────────────────────────────────────┘
```

設計要點：

- **執政官頭像 32×32 像素**，有名字，說話用「領主」稱呼玩家
- **`BLOCKED` 訊息與行動訊息同等重要**——沒做什麼也要說
- 離線 > 24 小時改為**逐日時間軸**，而非單一列表
- 「調整方針」直接跳到執政官頁，讓簡報成為調整的入口

同一份資訊，完全不同的體感。這也是遊戲曆（`14` §2）
與廢土敘事真正落地在每次登入第一秒的地方。

### 6.0b ★ 區域容量必須是一級資訊

補給／區域容量（見 `16`）是這套設計裡**最容易讓玩家困惑**的機制：
部隊莫名減員、糧耗突然暴漲，如果玩家看不懂原因，體驗會極差。

因此它不能是隱藏在數字後面的規則，必須在三個地方**主動顯示**：

| 位置 | 顯示內容 |
| --- | --- |
| **地圖（L2/L3）** | 區域格線與名稱；點擊區域顯示「我方容量 6,250 / 已駐 4,100」的容量條 |
| **派兵確認畫面** | 「抵達後該區將有 5,200 人，超出容量 1,100 人 → 每小時損兵 55」，紅字預警 |
| **戰報與通知** | 減員明確歸因：「第 47 區 · 鏽谷 補給不足，損失 128 人」 |

季節切換前 6 小時的預警也要包含容量變化：
「冬季將至：第 47 區的容量將由 6,250 降為 3,750，你目前駐有 5,100 人」。

**規則可以複雜，但後果必須可預期。** 玩家可以不懂公式，
但不能在打開遊戲時發現三千人不見了卻不知道為什麼。

### 6.1 戰報詳情的設計原則

玩家輸掉一場仗時，最挫折的不是輸，是**不知道為什麼輸**。
戰報必須能回答：

```
你的戰力 12,400
  ├ 基礎攻擊 14,200
  ├ 攻擊科技 +8%    → 15,336
  └ 士氣 ×0.81      → 12,422   ← 因為對方人口只有你的 1/3

對方防禦 15,800
  ├ 基礎防禦 11,900
  ├ 城牆 Lv8 +64%   → 19,516
  ├ 森林地形 +10%   → 21,468
  └ ⚠ 有 3 位盟友增援（+4,900）

結果：防守方勝，你的部隊全滅
```

每一行都可點擊查看該項的計算規則。這是社群信任的基礎，
也大幅減少客服與「這遊戲是不是有 bug」的爭議。

## 7. 效能與省電

| 措施 | 說明 |
| --- | --- |
| 分頁隱藏 | `visibilitychange` → `ticker.stop()`、SSE 5 分鐘後斷線 |
| 閒置降幀 | 無互動 5 秒 → 15fps；有互動立即回 60fps |
| 動畫節制 | 地圖上不做粒子特效、不做光暈；只有選取框與行軍箭頭會動 |
| 圖片 | 全部 PNG-8（256 色以內），符合調色盤限制後檔案極小 |
| 字體 | Zpix 用 `unicode-range` 子集化，只載入常用 3,500 字 |

## 8. PWA 與通知

- `manifest.json`：standalone、直向鎖定、maskable icon
- Service Worker：快取 app shell 與地形 chunk（stale-while-revalidate）
- **Web Push**（需使用者授權）：
  - 據點被攻擊（30 分鐘預警）
  - 行軍抵達
  - 建造／研究完成（可關閉）
  - 遺跡控制權變化（僅聯盟成員）
- 通知有**每小時上限 6 則**，避免變成騷擾

## 9. 無障礙

| 項目 | 措施 |
| --- | --- |
| 色盲 | 聯盟色已通過 deuteranopia 檢查；地圖可開「圖案疊加」模式（不同聯盟用不同斜線紋理） |
| 對比 | UI 文字對背景 ≥ 4.5:1；像素字建議 ≥ 7:1 |
| 觸控目標 | 所有可點元素 ≥ 44×44 px |
| 減少動態 | 尊重 `prefers-reduced-motion`，關閉所有轉場與閒置動畫 |
| 字級 | 提供「大字模式」，UI 文字放大 1.25×（像素字改用 2× 縮放） |

## 10. 本地化

- v1：**繁體中文**（主要）、English
- 所有文案走 i18n key，不寫死在元件中
- 像素字型需確認涵蓋兩種語系；英文用 Silkscreen，中文用 Zpix
- 數字格式化與時間顯示依 locale（`Intl.NumberFormat` / `Intl.RelativeTimeFormat`）
