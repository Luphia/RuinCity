# 06 · 聯盟系統

> 決策：**v1 就做基本版**。多人戰爭遊戲的留存核心來自社交，不能延到 v2。
> 但只做支撐「地緣關係 → 合作 → 共同目標」這條線的最小集合。

## 1. v1 範圍

| 功能 | v1 | 說明 |
| --- | --- | --- |
| 建立聯盟 | ✅ | 消耗 木 2,000 / 石 2,000；需主堡 Lv8 |
| **全場聯盟數上限** | ✅ | **15 個**。額滿後不可新建，只能加入既有聯盟 |
| **系統代碼** | ✅ | 建立時配發 2 位 **HEX 代碼（00–FF）**，賽季內唯一、不可更改 |
| 加入／申請 | ✅ | 公開招募 / 需審核 / 僅邀請 三種模式 |
| 成員上限 | ✅ | **60 人**（15 × 60 = 900，剛好容納全場）；AI 成員另計，上限 10 名 |
| 職級 | ✅ | 盟主 1 / 副盟主 ≤3 / 成員 |
| **斬首 Decapitation** | ✅ | 盟主據點被圍城 2 小時 → **全聯盟出局並結算**（見 §4） |
| 聯盟頻道 | ✅ | 即時文字聊天（SSE 推播） |
| **不可互相攻擊** | ✅ | 硬性規則，同盟成員之間所有攻擊型行軍被禁止 |
| **共享視野** | ✅ | 可見所有成員據點周圍 15 格的地圖動態層 |
| **增援盟友** | ✅ | Reinforce 行軍，部隊駐紮並計入對方防禦 |
| 聯盟色與旗標 | ✅ | 地圖上所有成員領土塗同一顏色，可自選 15 色之一 |
| 來襲廣播 | ✅ | 成員被攻擊時自動在頻道發出警報（座標 + ETA） |
| 求援按鈕 | ✅ | 一鍵發送求援，附偵查情報 |
| 聯盟排行榜 | ✅ | 依總領土 / 總戰力 / 遺跡控制時數 |
| 聯盟事件日誌 | ✅ | 加入退出、遺跡佔領、成員被攻破等，保留 7 天 |

## 2. v2 規劃（不在 v1）

| 功能 | 說明 |
| --- | --- |
| 聯盟科技 | 成員捐獻資源，解鎖全體加成 |
| 聯盟倉庫 | 集中資源池，盟主分配 |
| 集結攻擊 Rally | 多名成員的部隊在同一時間抵達同一目標 |
| 外交系統 | 同盟 NAP / 宣戰 / 附庸關係，地圖上以邊框樣式表示 |
| 聯盟聯邦 | 多個聯盟結成聯邦，共享視野但不共享遺跡增益 |
| 語音頻道 | 大概不做，玩家會自己開 Discord |

> **集結攻擊（Rally）刻意放到 v2**：它是聯盟戰的核心體驗，但實作複雜度極高
> （多來源不同距離的部隊需在同一時刻抵達，涉及最慢者對齊、中途取消、部分失效）。
> v1 用「約定時間各自發兵」來替代——玩家會自己在聊天室算行軍時間，
> 這其實是很多老玩家喜歡的部分。等 v1 驗證了戰鬥系統穩定再做 Rally。

## 3. 關鍵機制細節

### 3.1 增援 Reinforce

```
派遣：選擇同聯盟成員的據點或前哨營 → Reinforce 行軍
抵達後：
  - 部隊駐紮在對方位置，計入對方的守方戰力 D
  - 糧食由「派出方」持續支付（不會拖垮受援方）
  - 受援方看得到增援部隊的組成
  - 派出方可隨時「召回」，召回需再走一次行軍時間
  - 若受援方被攻破，增援部隊按一般規則承受損失
  - 若受援方退出聯盟，所有增援部隊立即自動召回
```

增援是聯盟最重要的功能：它讓「有人在你睡覺時幫你守家」成為可能，
這正是玩家願意加入聯盟並留下來的理由。

### 3.2 共享視野

```
可見範圍 = ∪ (每位成員核心據點為中心，半徑 15 格)
         ∪ (每座聯盟前哨營為中心，半徑 10 格)
         ∪ (每座控制中的遺跡為中心，半徑 20 格)
```

視野內可見：他人據點等級、領土歸屬、行軍箭頭（含兵力數量）。
視野外只能看到靜態地形與「有人佔領」的模糊色塊，看不到細節。

**這讓聯盟的地理形狀有戰略意義**：把成員排成一條線可以獲得長廊視野，
擠成一團則視野重疊浪費。玩家會為了視野而規劃彼此的落點。

### 3.3 退出與踢除

| 情境 | 規則 |
| --- | --- |
| 主動退出 | **6 小時**冷卻期後才能加入新聯盟；期間可被原聯盟成員攻擊 |
| 被踢除 | 立即生效，無冷卻 |
| 盟主退出 | 必須先轉讓盟主，否則無法退出 |
| 聯盟解散 | 僅盟主可執行，需二次確認；所有領土色歸中性灰 |
| 增援部隊 | 任何脫離情境下立即自動召回 |

6 小時冷卻的目的：防止「戰前跳槽」——在被攻擊前一刻跳到攻擊方聯盟以獲得免疫。
（原為 24 小時；在 12 天賽季裡等同於把玩家踢出賽季，過重。）

### 3.4 聯盟顏色與系統代碼

#### 顏色

**15 種預設色**（對應 15 個聯盟名額），賽季內不可重複。
色票在 `09-art-ux.md` §3 定義，都經過像素風調色盤校準，
並確保在 L3 戰略視圖（每格 2px）下彼此可辨識、通過紅綠色盲模擬。

#### ★ 系統代碼（2 位 HEX，00–FF）

除了玩家自訂的聯盟名稱與 5 字 tag，系統另外配發一組**不可更改的識別碼**：

```
格式：兩位十六進位，00 – FF（共 256 種）
配發：以賽季 seed 洗牌後的序列，依聯盟建立順序取出
      → 公平（不是先到先挑好號）且不可預測
唯一：賽季內唯一，且建立後永遠不可更改
顯示：[A7] 鐵鴉商會
```

**為什麼需要它**：

| 用途 | 說明 |
| --- | --- |
| **L3 戰略視圖** | 每格只有 2px，塞不下名稱——代碼是唯一讀得出來的識別 |
| **穩定識別碼** | 名稱與 tag 可以改，代碼不會。戰報、聯盟日誌、API 一律以代碼為準 |
| **跨賽季統計** | 歸檔頁與排行榜用代碼串接歷史 |
| **溝通效率** | 「A7 在鏽谷集結」比打全名快，且不會打錯 |

15 個聯盟只用掉 256 個代碼中的 15 個，
所以某些代碼（`00`、`FF`、`AA`、`DE`…）會成為賽季內的身分符號——
但因為是 seed 洗牌配發，**沒有人能搶**。這是純粹的運氣與談資。

### 3.5 AI 成員

玩家可邀請地圖上的 AI 玩家加入聯盟，AI 一律接受。

- **不計入 60 人上限**，另設 AI 上限 **10 名**
- AI 成員提供增援（其當前兵力的 30%）、繳交聯盟稅
- AI **不投票、不發言、不參與遺跡勝利判定**
- 聯盟列表中以 `◈` 前綴與灰階名牌明確標示

這給了小聯盟一條實質的成長管道：招不到真人時，
至少能靠 AI 撐起邊境防線。詳見 [`15-ai-players.md`](15-ai-players.md) §5。

## 4. ★ 斬首 Decapitation：聯盟的死亡條件

> **盟主的核心據點被攻陷，全聯盟立即出局並結算分數。**

這是整場賽季裡風險最高、也最戲劇化的機制。
它給每一個聯盟一個**看得見的弱點**，讓小聯盟有辦法擊倒大聯盟，
也讓「誰當盟主」從行政職位變成戰略決策。

### 4.1 主旗 Standard

盟主的核心據點自動獲得**主旗**狀態：

| 加成 | 值 |
| --- | --- |
| 固有防禦 | **×2**（`主堡等級 × 240`） |
| 駐軍上限 | **×1.5**（`(1,000 + 400 × 主堡等級) × 1.5`） |
| 地圖標示 | 顯示聯盟旗、HEX 代碼與主旗圖示，**所有玩家可見** |

盟主天生是全聯盟最硬的據點——但也是**唯一致命的那一個**。
而且它在地圖上藏不住。

### 4.2 斬首流程

```
前提：夏季（遊戲月 4 / D3）之後才可執行。春季不可斬首。

1. 以「攻擊 Attack」型行軍打贏盟主據點的守軍

2. 勝利後，攻方存活部隊自動進入「圍城 SIEGE」狀態，釘在該格
   - 不可主動離開，不可再派往別處
   - 持續消耗糧食，且受區域軍隊容量限制（見 16 §2）

3. 圍城計時 2 小時（真實時間）
   - 🚨 全服公告：「{HEX} {聯盟名} 的主旗正在被 {HEX} {攻方} 圍攻」
   - 被圍聯盟全員收到最高等級推播（無視通知頻率上限）
   - 任何玩家（不限聯盟）都可以派兵攻擊圍城部隊

4. 圍城部隊被擊退，或減員至 500 人口以下 → 斬首失敗，圍城解除

5. 圍城滿 2 小時 → 該聯盟進入 FALLEN（淪陷）
```

### 4.3 淪陷 FALLEN 的後果

| 對象 | 結果 |
| --- | --- |
| **全體成員** | 立即出局，積分**定格結算**並登上最終排行榜 |
| 成員領土 | 全部轉為**中立**（**不歸攻方所有**） |
| 成員核心據點 | 轉為「廢墟」地標，留在地圖上但不再運作 |
| 聯盟名額 | 釋出一個（15 名額之一），未結盟玩家可新建 |
| **執行方** | 賽季積分 **+1,500** + 全服公告 + 頭銜「斬旗者」 |
| 出局成員 | 進入觀戰模式，並可**立即登記下一場**（不受「同時只能一場」限制） |

**領土轉中立而非歸攻方**，是為了避免滾雪球過快：
斬首的獎勵是積分與消滅對手，不是直接繼承對方的版圖。
那些空出來的土地是留給**所有人**去搶的——這讓斬首之後緊接著一場混戰。

### 4.4 盟主轉讓：策略，不是漏洞

| 規則 | 說明 |
| --- | --- |
| 冷卻 | 轉讓後 **6 小時**內不可再轉讓 |
| 生效延遲 | 宣告後 **30 分鐘**才生效（主旗才轉移） |
| **圍城期間** | **完全不可轉讓** |

30 分鐘延遲與圍城禁令一起，讓轉讓無法用來緊急脫身。
它是**事前的部署決策**，不是事後的逃生門。

於是「誰當盟主」變成真問題：

- 位置最偏遠、最難被打到的人？（但他也離戰場最遠，指揮不便）
- 主堡等級最高、防禦最強的人？（但他也是最顯眼的目標）
- 一個沒人注意的小號？（但小號守不住，且主旗加成基於主堡等級）

**沒有安全的答案。** 而且對手看得到你的選擇。

### 4.5 這個機制為什麼值得承擔風險

| 它帶來 | 說明 |
| --- | --- |
| **弱者有翻盤路徑** | 一個 15 人的小聯盟若能精準斬首，可以直接抹掉一個 60 人強權 |
| **增援有了終極價值** | 保衛主旗是聯盟最高優先級，`增援 Reinforce` 從方便功能變成生死線 |
| **12 天賽季的節奏** | 出局在長賽季裡是災難，在 12 天賽季裡只是「這場結束了，下場 7 天內開始」 |
| **最戲劇化的兩小時** | 全服公告 + 倒數 + 所有人都可以介入。這是賽季敘事的高潮之一 |

### 4.6 邊界情況

| 情況 | 處理 |
| --- | --- |
| 盟主進入 AI 託管 | **仍可被斬首**。聯盟必須在盟主失聯前轉讓——這是真實的壓力 |
| 無聯盟的玩家 | 沒有主旗，不可被斬首（但也沒有交易、增援、共享視野） |
| 圍城中盟主退盟 | 不可退盟（與轉讓同規則） |
| 圍城方自己被斬首 | 兩邊同時淪陷；先達成 2 小時者判定為執行方 |
| 遺跡軍團攻擊盟主 | 可以打贏守軍，但**軍團不會圍城**——AI 不能終結真人的賽季 |

## 5. 反濫用

| 風險 | 對策 |
| --- | --- |
| 小號互餵資源 | 交易僅限同盟成員且**無稅**，改以資源轉移日上限 `500 × 主堡等級` 控制 |
| 幽靈聯盟佔遺跡 | 遺物只分配給 12 小時內登入過的成員；AI 成員不分配遺物 |
| 大聯盟壟斷 | 全場硬性上限 **15 個聯盟 × 60 人**；v1 不做聯邦。平均每陣營 5 個聯盟，確保陣營內部也有政治 |
| 大聯盟無敵 | **斬首機制**（§4）：規模再大也只有一個主旗，且它藏不住 |
| 假投降／跳槽 | 退出 **6 小時**冷卻（`TIME_SCALE`；12 天賽季裡 24 小時冷卻等同於永久除名） |
| 聊天室洗版／騷擾 | Rate limit（10 則/分鐘）、成員檢舉、盟主可禁言 |

## 6. 資料模型摘要

```
alliances(id, season_id, name, tag, hex_code, color, recruit_mode,
          leader_id, status, fallen_at, felled_by_alliance_id, created_at)
alliance_members(alliance_id, player_id, rank, joined_at)
alliance_events(id, alliance_id, type, payload jsonb, created_at)
sieges(id, season_id, target_alliance_id, attacker_alliance_id,
       at_x, at_y, started_at, resolves_at, status)
chat_messages(id, channel_type, channel_id, player_id, body, created_at)
```

`alliances.status`：`ACTIVE | FALLEN`。
`hex_code` 為 2 位十六進位字串，`UNIQUE (season_id, hex_code)`。

`channel_type` 支援 `ALLIANCE` / `GLOBAL` / `DIRECT`，v1 只開 `ALLIANCE`。
完整 schema 見 [`08-data-model.md`](08-data-model.md)。
