# 00 · 遊戲總覽

## 1. 一句話定位

**RuinCity** 是一款在手機瀏覽器上就能玩的像素風多人戰爭策略遊戲。
玩家在 500×500 的廢土地圖上經營一座 2×2 的核心據點，向外佔領領土、招募軍隊、
組成聯盟，最終爭奪三座古老遺跡的控制權以贏得賽季。

## 2. 目標平台與客群

| 項目 | 決策 |
| --- | --- |
| 平台 | 手機瀏覽器優先（PWA），桌機自適應 |
| 直橫向 | 直式為主，單手可操作 |
| 網址 | ruincity.com |
| 目標客群 | 喜歡 Travian / 部落衝突 / COK 但受不了現代 SLG 課金壓力的玩家 |
| 單次遊玩時長 | 3–10 分鐘 ×每日 3–5 次（碎片化） |
| 賽季長度 | 6–8 週 |

## 3. 核心體驗支柱

1. **看得見的擴張**
   領土是地圖上實際被塗色的格子。玩家的成長不是數字，是版圖。
   打贏一場仗會**當場改變地圖的形狀**。

2. **不在線也在推進，但不會在線就無敵**
   行軍計時制：所有動作都是「下指令 → 等時間 → 結算」。
   離線期間資源持續累積、行軍持續前進，不需要盯著螢幕。
   但**攻擊會在你離線時抵達**——這是張力來源，也是聯盟存在的理由。

3. **地圖即社交**
   你的鄰居是誰、遺跡在哪個方向、哪條路線能繞過山脈，
   決定了你要跟誰結盟、跟誰開戰。地緣關係先於好友列表。

4. **有終點的戰爭**
   三座遺跡被同一個聯盟同時掌控滿一定時間，賽季結束、地圖重置。
   沒有無限膨脹的伺服器，也沒有「開服三個月後新人再也追不上」。

5. **每一次升級都是一次放棄**
   核心據點只有 4 格、核心建造佇列永遠只有 1 條、資源不可跨類轉換。
   你想要的東西永遠比你能負擔的多，**選擇本身就是玩法**。
   而因為全員同時開賽，你的每一個取捨都會被鄰居的取捨立刻檢驗——
   當你在升主堡時，隔壁那個人正在練劍士。

6. **同一條起跑線**
   事先登記、全員同時進入。沒有先到者優勢，沒有晚到者補償。
   出生點是批次最佳化出來的，公平性數值在開戰前公開讓所有人檢查。

## 4. 設計原則（做取捨時的準則）

| # | 原則 | 含意 |
| --- | --- | --- |
| P1 | **伺服器是唯一真相** | 所有結算在後端，前端只做顯示與預測。任何客戶端數值都不可信。 |
| P2 | **省電優於華麗** | 手機網頁遊戲。不做常駐 WebSocket tick，不做每秒動畫。 |
| P3 | **可離線推進** | 玩家關掉分頁後，資源、建造、行軍照常。回來時一次結算。 |
| P4 | **付費不買戰力** | 只賣外觀、建築佇列格數、介面便利。不賣兵、不賣資源、不賣加速戰鬥。 |
| P5 | **保護新人與弱者** | 新手保護期、士氣懲罰（大打小戰力打折）、重複劫掠遞減收益。 |
| P6 | **能刪的系統就先不做** | v1 只做支撐核心循環的最小集合，其餘進 v2。 |
| P7 | **每個決策都要有取捨** | 核心據點只有 4 格，蓋了兵營就蓋不了倉庫。稀缺產生流派。 |

## 5. 核心遊戲循環

### 5.1 短循環（單次登入，3–10 分鐘）

```
登入
 └─ 結算離線期間的一切（資源、建造完成、行軍抵達、戰報）
     └─ 讀戰報 / 看地圖變化
         └─ 分配資源：升級建築 or 招兵
             └─ 派遣行軍：突襲鄰居 / 偵查 / 佔領新領土 / 增援盟友
                 └─ 關閉分頁（計時器繼續跑）
```

### 5.2 中循環（單日～單週）

```
擴張領土 → 領土產出更多資源 → 資源養更多兵
    ↑                                    ↓
守住領土 ←─ 兵力提供防禦與嚇阻 ←─ 掠奪鄰居補充資源
```

### 5.3 長循環（整個賽季）

```
登記期（開賽前 7 天）
  選陣營（決定生在哪座遺跡旁）、選出生帶（安全 vs 接近終局）、揪同行小隊
       ↓
封盤期（開賽前 24 小時）
  地圖生成與出生點批次分配完成，公布地圖預覽與公平性驗證數值
  玩家看到自己的座標與鄰居 → 社交網路在第一顆資源產出前就開始編織
       ↓
▶ T = 0 全員同時開戰 ◀
       ↓
新手期（第 1 週）
  獨自發展、清怪、認識鄰居
  三個陣營區域開始演化出不同性格（掠奪 / 種田 / 血戰）
       ↓
擴張期（第 2–3 週）
  領土衝突、加入聯盟、劃分勢力範圍
       ↓
遺跡期（第 4–6 週）
  遺跡守衛被清空、聯盟開始爭奪遺跡、大規模會戰
       ↓
終局（第 6–8 週）
  某聯盟同時控制三座遺跡滿 24 小時 → 賽季結束
       ↓
結算與傳承
  排行榜、頭銜、永久外觀、少量傳承加成 → 新賽季地圖重生
```

## 6. 已定案的關鍵決策

| 決策點 | 選擇 | 理由 |
| --- | --- | --- |
| 戰鬥時間模型 | **行軍計時制** | 手機網頁最省電、可離線推進、後端不需長連線 tick |
| 據點成長 | **固定 2×2 核心 + 可佔領外部相鄰領土** | 核心格稀缺產生建築取捨；領土擴張讓成長可視化 |
| 遺跡定位 | **賽季勝利目標** | 給戰爭一個終點，避免伺服器永久膨脹 |
| 聯盟系統 | **v1 就做基本版** | 多人戰爭遊戲的留存核心來自社交，不能延後 |
| 入場方式 | **事先登記 + 全員同時進入** | 消滅「晚加入吃虧」問題；N 已知讓出生點分配可驗證公平；登記表單本身成為第一個決策場景 |
| 資源與佇列 | **核心建造佇列永遠 1 條 + 資源不可跨類轉換** | 讓「升什麼」成為持續的痛苦選擇，而非一次性 build 決定 |

> 註 1：原始構想為 4×4 據點，經討論後調整為 **2×2 核心 + 外部領土佔領**。
> 4 格核心的稀缺性帶來更強的 build 取捨，而擴張感由領土系統承擔。
>
> 註 2：原設計為「外環螺旋入場」（依註冊順序由外向內填入）。
> 那是為了補償晚加入者而做的補丁；改為同時開賽後問題本身消失。
> 詳見 [`13-season-registration.md`](13-season-registration.md)。

## 7. 商業模式（v1 之後）

| 項目 | 是否販售 | 說明 |
| --- | --- | --- |
| 據點／單位外觀皮膚 | ✅ | 純外觀，賽季結束後永久保留 |
| 第二條建造佇列 | ✅ | 便利性，不增加產出上限 |
| 地圖書籤 / 進階戰報分析 | ✅ | 介面便利 |
| 資源、兵力、加速戰鬥 | ❌ | 違反 P4 |
| 提前結束行軍 | ❌ | 直接破壞行軍計時制的核心張力 |
